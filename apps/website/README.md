# @sairn/website

Marketing site served at **sairn.ai**. Built with Astro 7 (Vite 8) + Tailwind 4.3. Static output, no JS framework on the client. Needs Node ≥22.23.4 (Astro 7's minimum; the rest of the repository stays on ≥22.15.0), see [Platform](#platform-2026-10-26-实施修订).

The trading app lives at **app.sairn.ai** (`apps/terminal`).

## Local

```bash
pnpm --filter @sairn/website dev      # http://localhost:3010
pnpm --filter @sairn/website test     # source-only tests (tests/*.test.mjs), run before the build
pnpm --filter @sairn/website build    # → dist/
pnpm --filter @sairn/website test:dist  # tests that read dist/ (tests/built/*.test.mjs), run after the build
pnpm --filter @sairn/website preview
pnpm --filter @sairn/website markets:snapshot          # refresh src/data/market-structure.json, then the market icons
pnpm --filter @sairn/website markets:icons            # refresh src/assets/coins/ and src/data/market-icons.json only
pnpm --filter @sairn/website markets:snapshot --check  # compare the committed snapshot and configs with the exchange
pnpm --filter @sairn/website terminal:check            # release precondition: the live terminal carries T1 and ADR 0042
```

Behind an HTTP proxy, Node's `fetch` needs `NODE_USE_ENV_PROXY=1` for the snapshot and terminal-check scripts.

## Platform (2026-10-26 实施修订)

Upgraded from Astro 5.14.6 / Tailwind 4.0.6 to **Astro 7.4.2** (Vite 8 with Rolldown, the Rust compiler), **tailwindcss and @tailwindcss/vite 4.3.3** and **@astrojs/sitemap 3.7.4**, all pinned; Vite comes from Astro, so the Tailwind plugin and Astro share one copy. Only this package's importer changed in `pnpm-lock.yaml`. `tests/platform-contract.test.mjs` pins the versions and the settings below.

- **Node:** `engines.node` is `>=22.23.4`, Astro 7.4.2's own minimum; Astro refuses to start on older Node (checked on 22.18.0). `website-build.yml` and `website-markets-check.yml` pin Node 22.23.4; the other workflows keep 22.15.0, where installing the workspace only warns about this package's engines.
- **Migration settings** (Astro [v6](https://docs.astro.build/en/guides/upgrade-to/v6/) and [v7](https://docs.astro.build/en/guides/upgrade-to/v7/) guides): `compressHTML: true`, because v7's default `'jsx'` drops the spaces between inline elements and text on separate lines ("risk.Risk disclosure"); `z` from `astro/zod` (Zod 4) and `z.looseObject()` in place of `.passthrough()` in `src/content.config.ts`; `markdown.syntaxHighlight: false`, because Shiki's inline styles fail the CSP (the legal pages and the empty blog have no code blocks). Nothing else in the guides applies: no i18n, `<ViewTransitions />`, `Astro.glob()`, `astro:transitions` internals, `src/fetch.ts`, remark/rehype plugins or numeric `getStaticPaths` params. The legal Markdown now renders with Sätteri; heading ids are unchanged and the only text difference is whitespace between table cells.
- **Fonts API:** `astro.config.mjs` `fonts` serves the two Fontsource latin files through the local provider (offline, from `node_modules`), and `<Font />` in `Base.astro` writes their `@font-face` rules, the CSS variables `--font-plex-sans` / `--font-plex-mono` (which `--font-sans` / `--font-mono` point to) and the one preload, for Plex Sans. Files land in `_astro/fonts/`. Generated fallback metrics are off (`optimizedFallbacks: false`): Astro 7.4.2 writes the metric-matched Arial / Courier New face without the subset's `unicode-range`, so it would draw every glyph outside the latin files (the → of every link, the ▲▼ of 24h changes) instead of the system font; the stacks stay as before. During `astro build` the Fonts API listens on a local port, so a sandbox without local binding fails with `listen EPERM`.
- **CSP:** `security.csp` gives every page a `<meta http-equiv="content-security-policy">` with `default-src 'self'`, `connect-src 'self' https://api.hyperliquid.xyz wss://api.hyperliquid.xyz`, `img-src 'self' data:`, `media-src 'self'`, `font-src 'self'`, and Astro's own hash lists for `script-src` / `style-src` (no `'unsafe-inline'`). The two `is:inline` blocks in `Base.astro` (the `js` class script and the motion tokens) are hashed through `Astro.csp` from the exact emitted text (`src/lib/csp.ts`). Astro writes the meta at the end of `<head>`, so it governs everything after it (stylesheet, module scripts, fetches, the WebSocket, images); a meta policy cannot carry `frame-ancestors`, `report-to` or `sandbox`, which stay with the CloudFront response-headers policy (plan §8). The policy only works in `astro build` / `preview`, not in `astro dev`.
- **CSS platform features** (all progressive and, where they move anything, inside `prefers-reduced-motion: no-preference`):
  - cross-document view transitions (`@view-transition { navigation: auto; }`): a 200 ms root cross-fade between the home page and the legal and support pages, with the header kept still through `view-transition-name: site-header`; no `<ClientRouter />`;
  - `sibling-index()` staggers, behind `@supports (animation-delay: calc(sibling-index() * 1ms))`: the account points, the features tab list and the stats rise one after another on the scroll-driven reveal (`.reveal-stagger`), and market rows follow one another when a category is switched;
  - `@starting-style` entries for tab panels the visitor switches to (`tabs.ts` sets `data-tabs-switched`, so the first render never animates) and for opened disclosures (FAQ, stats method, class `disclosure`); where `::details-content` and `interpolate-size: allow-keywords` exist, the disclosure height opens smoothly as well (the one transition that is not transform or opacity, registered in `motion-contract`);
  - container queries (`@container` with `--container-cards` 36rem, `--container-table` 43.875rem, `--container-split` 60rem) for the account points, the market table and the features layout; each size equals the block's width at the viewport breakpoint it replaced, so the switch points are unchanged at full width;
  - glow tints derived with `color-mix(in oklab, var(--marketing-accent) N%, transparent)` (and `var(--action)` for the neutral glow); Tailwind adds a non-`color-mix` fallback that no browser it supports uses;
  - `text-wrap-style: balance` on headings and `pretty` on body copy (the longhands, so `whitespace-nowrap` keeps working);
  - Tailwind 4.3's `scrollbar-none` utility in place of the `[scrollbar-width:none]` arbitrary property.

## Market data

Plan: [docs/website-plan.md](../../docs/website-plan.md) §7 and R10. Market and deployer names, counts and Pre-IPO facts come only from these sources:

| File | Holds |
| --- | --- |
| `src/data/market-structure.json` | Generated by `markets:snapshot`, never edited by hand: per dex with at least one listed market, the dex fullName and its listed markets (category, displayName, szDecimals, onlyIsolated, growthMode, deployerFeeScale, 24h notional volume). No addresses. |
| `src/assets/coins/`, `src/data/market-icons.json` | Generated by `markets:icons` (also run by `markets:snapshot`), never edited by hand: the icon of every market the site renders, from the terminal's source `https://app.hyperliquid.xyz/coins/<coin>.svg`, cleaned by `scripts/svg-sanitize.mjs` (`:` becomes `--` in file names), with the source URL and fetch time; markets the source has no icon for are listed as fallbacks and show a monogram (`MarketIcon.astro`). |
| `src/config/featured-markets.ts` | `FEATURED_MARKETS`: the ten ticker markets by category quota (`FEATURED_MARKET_QUOTAS`: Pre-IPO 2, pinned first and marked for the hero; Stocks 2; Indices 1; Commodities 2; FX 1; Crypto 2), picked by 24h volume within each category, with the deployer's own name for each and where that name comes from (`nameSource`). They also lead the examples on the category cards. Edit it by hand when the snapshot reports a featured market delisted or recategorized. |
| `src/config/deployers.ts` | `PRE_IPO_TERMS`: per Pre-IPO coin the valuation unit (US$ of implied valuation per US$1 of price), the scheduled settlement date and whether the deployer can settle early on notice, each with its source URL and read date. A Pre-IPO market without an entry shows no unit, valuation or date, only a link to the deployer's documentation. `PRE_IPO_DOCS`: for each Pre-IPO coin without terms, the deployer page that lists it, its read date and whether the deployer quotes the price per share of the company; `tests/markets-structure.test.mjs` requires one for every such coin. |
| `apps/terminal/src/config/hip3-deployers.ts` | Deployer documentation links, read from the terminal rather than copied. |

`src/lib/markets/structure.ts` loads them for the home page and throws on import when the snapshot contains an address, a featured market is missing, delisted or recategorized, a listed dex has no documentation link, or a `deployers.ts` entry no longer matches the snapshot. The date rules (snapshot older than 7 days, a `deployers.ts` source last read more than 90 days ago or dated ahead, a scheduled settlement date that has passed) run in `assertMarketStructureCurrent()`, which `src/pages/index.astro` calls, so the build fails on them while the source tests never read the clock. Links into the terminal come from `src/lib/terminal-links.ts`, which pages without market data import instead. `markets:snapshot` applies the same rules to fresh exchange data; `--check` also fails when a published Pre-IPO row was delisted or recategorized. `src/lib/markets/live.js` holds the pure functions of the live numbers (request plan and weight budget, fail-closed validation, freshness, 24h change, implied valuation, price precision) for the browser script and the tests.

Refresh the snapshot before every release and review its diff as its own commit (the release runbook records `fetchedAt` and the changes in the task record). When the exchange moves a Pre-IPO market to another category after its listing, the refresh commit deletes its `deployers.ts` entries; when a new Pre-IPO market appears without a verified unit, it adds the deployer page that lists the market to `PRE_IPO_DOCS` (on 2026-11-04: `xyz:JIO` converted to a stock, `para:ANTH` added). The daily `Website Market Snapshot` workflow (`.github/workflows/website-markets-check.yml`) runs `markets:snapshot --check` on the default branch with read-only permissions; a red run means the next release needs a refresh, and the workflow never writes the snapshot itself.

`src/scripts/live-markets.ts` drives every live number on the home page: the stats band and ticker in 02 and the price rows of the 03 market tabs. It starts in an idle callback after `load`, runs only while one of those regions is at least 10% visible, the document is visible, updates are not paused and the tab holds the `sairn-site-live` Web Lock, stops 30 s after they leave the viewport or the page is hidden, and removes a market as soon as the exchange reports it delisted. It requests the main dex and every dex the page shows (main, io and xyz first, then the other dexes of the 03 rows: para in the 2026-11-04 snapshot), within 60 weight per rolling minute. The stats band keeps two labelled groups: the market catalogue (listed markets and deployers, from the dated snapshot) and live activity, which sums 24h notional volume and open interest × mark price with Big.js over exactly the venues its header names (core perps, EntropyIO, XYZ), shows a total and its as-of time only while all of them are current, and explains the method, including that volume and open interest are not fillable depth, in a `<details>` disclosure. The same Pause control stops the ticker's marquee (WCAG 2.2.2); the ticker only moves once that control is wired, never under reduced motion, and is a scroll-snap row otherwise. Without JavaScript or valid data the names and links render and the number slots stay empty.

`src/scripts/tabs.ts` wires every `[data-tabs]` block (hero preview, 03 markets, 04 features) as WAI-ARIA tabs: it sets `aria-orientation` from the list's actual layout (and keeps it current), so the arrow keys follow it, makes panels without a control of their own focusable, hides the unselected panels and marks the block `data-tabs-ready`. The markup renders every static panel, so without JavaScript the tab lists are hidden and every panel shows with its heading; with JavaScript the later panels (`data-tabpanel-deferred`) wait hidden before first paint, and a block still unmarked after `load` (the module failed) falls back to the no-JavaScript layout. `tests/built/tabs-browser.test.mjs` checks all four cases in Chromium. `src/scripts/open-book.ts` is the hero's Live market view, loaded only when that tab is first selected: one WebSocket to the public API (`l2Book`, `bbo`, `trades` for BTC, no info-endpoint weight), a recorded poster until 15 s of valid data, a price scale with the mid price tagged, a time scale counted back from now and an HTML legend, Pause, the `sairn-site-book` Web Lock, a connection budget, and no automatic start under reduced motion or Save-Data.

## Deploying

The website is a static build uploaded to a private S3 bucket behind CloudFront. Follow the [website release runbook](../../deploy/website/README.md): it lists the prerequisites for the sairn.ai domain, the cache groups, the upload and invalidation commands, the post-release checks and the rollback. Nothing in it is automated.

The terminal has a separate [CloudFront + S3 + Lambda deployment workflow](../../deploy/cloudfront/README.md); its `deploy.mjs` only handles the terminal build. `vercel.json` in this directory is left over from an earlier Vercel setup and is not used by CI or the current hosting.

### Why two deployments, not one?

The terminal is a TanStack Start application with edge API endpoints. The website is fully static. Separate delivery keeps their build, runtime and caching requirements independent.

## Content rules

- Product claims must match the terminal, and the live terminal's `build-meta.json` release is checked against the site's claims before each release (R14, see the release runbook).
- Images that can change (the hero screenshots) live in `src/assets/` and are imported, so Astro emits them under content-hashed `_astro/` URLs. The hero screenshots are captured from the live, signed-out terminal with `node apps/website/scripts/capture-hero.mjs` (Playwright from `apps/terminal`; headless Chromium needs an unsandboxed shell on macOS). It opens `/trade/BTC` and waits for the full workspace (chart, order book and order form), refuses a page showing a signed-in session, a wallet address, an open HIP-3 deployer disclaimer, any other open dialog or a test marker, writes `terminal-desktop.jpeg` (1600×900) and `terminal-mobile.jpeg` (the top 390×604 of a 390×844 viewport at 2×: order form and book), and records the URL, UTC time and live `build-meta.json` in `src/assets/terminal-capture.json`, from which the hero caption is rendered. The six Features screenshots come from `node apps/website/scripts/capture-features.mjs` (same guards, records `src/assets/features/features-capture.json`), then `node apps/website/scripts/optimize-images.mjs` encodes them, the hero screenshots (AVIF within the plan's 80 KB desktop / 45 KB phone budget; the JPEG stays the `<img>` fallback) and the Open Book posters to AVIF and WebP next to their JPEG sources with the sharp that Astro installs, so the build needs no image service. The Open Book posters themselves come from `node apps/website/scripts/render-open-book-posters.mjs` after a build: it replays the stored recording (`designs/website-hero-prototype/recorded/`, named in `src/assets/open-book/poster.json`) through the site's own canvas code and saves the last frame, so the posters carry the same scales as the live view. Files in `public/` keep a fixed URL; only put files there whose URL must stay stable (favicon, social card, robots.txt).

## Design notes

Plan: [docs/website-plan.md](../../docs/website-plan.md) §4 (block order) and §6 (visual and motion).

- **Home page:** blocks in the plan's order, each a component: 01 `Hero` (with the three benefits under the preview), `AccountExecution` (`#account`, the short account-and-execution explainer), 02 `LiveMarkets` and 03 `Markets` (one shared `[data-cta-group]` in `index.astro`), 04 `Features`, 06 `Start`, 07 `Fees`, 08 `Trust` (`#security`, Fig. 1 and the checklist), 09 `Faq` with the closing CTA, 10 `FactsBlock` and `Footer`. Block 05 (video) is not rendered until the operator's video exists. `SectionHeader` gives every block the same mono label, H2 and optional intro on a 12-column grid.
- **Colour:** light by default ([ADR 0044](../../docs/adr/0044-website-light-default-theme.md), pending the operator's confirmation). The first `:root` block of `src/styles/global.css` holds the light colour tokens (colours only; `brand-contract` reads every value there): paper canvas `--bg-base` #fafaf5 and band `--bg-band` #f5f4ee from the logo kit, white cards, headings in the logo's wordmark ink #08262e and body text in the neutral action ink. `.surface-dark, :root[data-theme="dark"]` holds the dark set (graphite canvas #12131a, window #0F1A1F, overlay #212d33): every product window (hero preview, feature screenshots) uses it, and `?theme=dark` switches the whole page for comparison (`src/lib/theme.ts`, hashed into the CSP). Filled buttons use the neutral `--action`; `--signal` is kept to focus, selection, prose links and the live indicator; marketing emphasis is `--marketing-accent` (ADR 0043). Up and down colours equal the terminal's market colours of the same theme (`tests/brand-cross-app.test.mjs`).
- **Buttons:** one style across the site (operator decision 2026-10-26, "style 4"): a pill, with a round arrow chip on the right for links and actions (↗ leaves the site, → stays on it, ↓ jumps down the page) and none for toggles. Use `src/components/ButtonLink.astro` for links and `Button.astro` for `<button>` elements (`pressed` makes it an `aria-pressed` toggle); both take `variant` (`primary` on the neutral `--action`, `secondary` on the panel with a hairline), `size` (`lg` 48px, `md` 40px, `sm` 36px; 44px on phones) and `icon`, and forward every other attribute. The `.btn*` rules in `global.css` sit outside `@layer` so no utility can override them; call sites add layout classes only. Tabs are pill segments without a chip. `tests/button-contract.test.mjs` and `tests/built/buttons.test.mjs` pin the classes, the unlayered rules, contrast in both themes and every terminal CTA's chip.
- **Type:** IBM Plex Sans Variable 5.2.8 (latin, preloaded, `font-display: block` as in the terminal) for headings and body; IBM Plex Mono 5.3.0 (latin 400, not preloaded, `swap`) for numbers, codes and labels, both through the Astro Fonts API. Every number is `tabular-nums` (set on `body`).
- **Motion:** `src/lib/motion.ts` reads `brand/loader/sairn-motion.tokens.json` at build time and `Base.astro` writes the durations and easings as `--motion-*` properties; `global.css` uses nothing else. Only transform and opacity move (plus the buttons' box-shadow as they lift), default styles are the final state (`.reveal` is offset only once `Base.astro` has set `motion` on `<html>`), and nothing moves under `prefers-reduced-motion`. `tests/motion-contract.test.mjs` pins this.
- **Fees:** the HIP-3 example in 07 is computed at build time from the snapshot by `src/lib/markets/fees.ts`, with the terminal's fee rule; `tests/fees.test.mjs` runs the terminal's own `applyMarketFeeScale` against it.
