# @sairn/website

Marketing site served at **sairn.ai**. Built with Astro + Tailwind v4. Static output, no JS framework on the client.

The trading app lives at **app.sairn.ai** (`apps/terminal`).

## Local

```bash
pnpm --filter @sairn/website dev      # http://localhost:3010
pnpm --filter @sairn/website test     # source-only tests (tests/*.test.mjs), run before the build
pnpm --filter @sairn/website build    # → dist/
pnpm --filter @sairn/website test:dist  # tests that read dist/ (tests/built/*.test.mjs), run after the build
pnpm --filter @sairn/website preview
pnpm --filter @sairn/website markets:snapshot          # refresh src/data/market-structure.json
pnpm --filter @sairn/website markets:snapshot --check  # compare the committed snapshot and configs with the exchange
pnpm --filter @sairn/website terminal:check            # release precondition: the live terminal carries T1 and ADR 0042
```

Behind an HTTP proxy, Node's `fetch` needs `NODE_USE_ENV_PROXY=1` for the snapshot and terminal-check scripts.

## Market data

Plan: [docs/website-plan.md](../../docs/website-plan.md) §7 and R10. Market and deployer names, counts and Pre-IPO facts come only from these sources:

| File | Holds |
| --- | --- |
| `src/data/market-structure.json` | Generated by `markets:snapshot`, never edited by hand: per dex with at least one listed market, the dex fullName and its listed markets (category, displayName, szDecimals, onlyIsolated, growthMode, deployerFeeScale, 24h notional volume). No addresses. |
| `src/config/featured-markets.ts` | `FEATURED_MARKETS`: the ten ticker markets by category quota (`FEATURED_MARKET_QUOTAS`: Pre-IPO 2, pinned first and marked for the hero; Stocks 2; Indices 1; Commodities 2; FX 1; Crypto 2), picked by 24h volume within each category, with the deployer's own name for each and where that name comes from (`nameSource`). They also lead the examples on the category cards. Edit it by hand when the snapshot reports a featured market delisted or recategorized. |
| `src/config/deployers.ts` | `PRE_IPO_TERMS`: per Pre-IPO coin the valuation unit (US$ of implied valuation per US$1 of price), the scheduled settlement date and whether the deployer can settle early on notice, each with its source URL and read date. A Pre-IPO market without an entry shows no unit, valuation or date, only a link to the deployer's documentation. |
| `apps/terminal/src/config/hip3-deployers.ts` | Deployer documentation links, read from the terminal rather than copied. |

`src/lib/markets/structure.ts` loads them for the home page and throws on import when the snapshot contains an address, a featured market is missing, delisted or recategorized, a listed dex has no documentation link, or a `deployers.ts` entry no longer matches the snapshot. The date rules (snapshot older than 7 days, a `deployers.ts` source last read more than 90 days ago or dated ahead, a scheduled settlement date that has passed) run in `assertMarketStructureCurrent()`, which `src/pages/index.astro` calls, so the build fails on them while the source tests never read the clock. Links into the terminal come from `src/lib/terminal-links.ts`, which pages without market data import instead. `markets:snapshot` applies the same rules to fresh exchange data; `--check` also fails when a published Pre-IPO row was delisted or recategorized. `src/lib/markets/live.js` holds the pure functions of the live numbers (request plan and weight budget, fail-closed validation, freshness, 24h change, implied valuation, price precision) for the browser script and the tests.

Refresh the snapshot before every release and review its diff as its own commit (the release runbook records `fetchedAt` and the changes in the task record). The daily `Website Market Snapshot` workflow (`.github/workflows/website-markets-check.yml`) runs `markets:snapshot --check` on the default branch with read-only permissions; a red run means the next release needs a refresh, and the workflow never writes the snapshot itself.

`src/scripts/live-markets.ts` drives the live strip on the home page: it starts in an idle callback after `load`, runs only while the strip is at least 10% visible, the document is visible, updates are not paused and the tab holds the `sairn-site-live` Web Lock, stops 30 s after the strip leaves the viewport or the page is hidden, and removes a market as soon as the exchange reports it delisted. Without JavaScript or valid data the names and links render and the number slots stay empty.

## Deploying

The website is a static build uploaded to a private S3 bucket behind CloudFront. Follow the [website release runbook](../../deploy/website/README.md): it lists the prerequisites for the sairn.ai domain, the cache groups, the upload and invalidation commands, the post-release checks and the rollback. Nothing in it is automated.

The terminal has a separate [CloudFront + S3 + Lambda deployment workflow](../../deploy/cloudfront/README.md); its `deploy.mjs` only handles the terminal build. `vercel.json` in this directory is left over from an earlier Vercel setup and is not used by CI or the current hosting.

### Why two deployments, not one?

The terminal is a TanStack Start application with edge API endpoints. The website is fully static. Separate delivery keeps their build, runtime and caching requirements independent.

## Tests

The rule numbers below are those of [docs/website-plan.md](../../docs/website-plan.md) §9.

- `test` (`tests/*.test.mjs`) reads only the sources, so it runs before the build; `pnpm test:brand` at the repository root runs it in CI.
  - `copy-contract.test.mjs` scans the text files under `src/`. It fails on retired claims (open source, MIT, self-hosting, a hard-coded leverage maximum such as "50×", 19+ chains, LiFi, "no accounts", "no backend", a builder fee on "every order") and on the plan's wording rules: R2 ("not securities", "invest in", "own the/a/shares", "buy … stock"), R3 ("market cap"), R5 ("full/max leverage", "leverage multiplier", "same/shared margin", cross margin in a HIP-3 sentence), R9 (unqualified "your keys", "signed locally") and R12 ("No KYC", latency in ms outside stylesheets, VPN, exchange and wallet brands, the chart library's trademark, "Live on mainnet", yield or return promises, comparisons with the official app). R10 rejects dex-prefixed coins (`xyz:…`, `io:…`) written in components, pages, layouts or scripts; R11 rejects brand names and domains from `brand/brand.json` anywhere in `src/` outside `src/config/brand.ts`, except the literals it lists with a reason. It also pins the fee figures to `apps/terminal/src/config/hyperliquid.ts` and the hero screenshots to their capture record.
  - `brand-contract.test.mjs` pins the brand colours, contrast and logo sources; `markets-*.test.mjs` cover the snapshot rules and the live-data functions with recorded responses, judged at the latest date the snapshot and `deployers.ts` name rather than today. The ΔE76 test keeps every colour token at least 15 from Hyperliquid's #97fce3, #03211c and #23524C (near-black neutrals exempt); `--signal` and `--signal-hover` are listed as pending exceptions until the operator decides on the brand accent.
- `test:dist` (`tests/built/*.test.mjs`) reads `dist/` after `astro build`, and `website-build.yml` runs it after the build step. It checks that no `gatu` remains in the build, the risk sentence in every `[data-cta-group]` and every `<section>` that links into the terminal with `utm_source=website` (R6; the header and the four legal pages are listed exceptions), the deployer names and the "does not review" sentence in the markets block (R1), "not shares" in every block that references companies (R2), the deployer-pricing note next to every 24/7 claim (R4), restricted-location sentences linking to an anchor that exists in `/terms/` (R7), the FAQPage structured data against the visible FAQ, `/blog/` noindex and out of the sitemap, the built brand values and the hero caption. `tests/built/html.mjs` is the small HTML reader these tests use. `live-markets-dom.test.mjs` runs `src/scripts/live-markets.ts` on the built home page in jsdom with a fake clock, fetch, Web Lock and IntersectionObserver: numbers only from validated answers, nothing sent while paused or while another tab holds the lock, stale numbers cleared (also on a back-forward-cache restore), delisted markets removed from 02 and 03 but not from the hero sentence, hung requests timed out, and the strip cleared with its lock released once retries are used up. jsdom is not a browser, so this does not replace a real-browser check.

## Content rules

- Product claims must match the terminal, and the live terminal's `build-meta.json` release is checked against the site's claims before each release (R14, see the release runbook).
- Images that can change (the hero screenshots) live in `src/assets/` and are imported, so Astro emits them under content-hashed `_astro/` URLs. The hero screenshots are captured from the live, signed-out terminal with `node apps/website/scripts/capture-hero.mjs` (Playwright from `apps/terminal`; headless Chromium needs an unsandboxed shell on macOS). It opens `/trade/BTC` with the market selector at Traditional Finance, Pre-IPO, refuses a page showing a signed-in session, a wallet address, an open HIP-3 deployer disclaimer or a test marker, writes `terminal-desktop.jpeg` (1600×900) and `terminal-mobile.jpeg` (390×844 at 2×), and records the URL, UTC time and live `build-meta.json` in `src/assets/terminal-capture.json`, from which the hero caption is rendered. Files in `public/` keep a fixed URL; only put files there whose URL must stay stable (favicon, social card, robots.txt).

## Design notes

- **Theme:** uses the same token system as `@sairn/ui` (a trimmed subset is inlined into `src/styles/global.css` so the website has zero workspace dependencies).
- **Type:** Inter Variable for sans-serif text and Instrument Serif for display text, defined in `src/styles/global.css`. Numbers use `tabular-nums` via the `.tabular` utility.
- **Inspiration:** [midday.ai](https://midday.ai) — single-column layout, restrained motion, every section is a short headline + one-line subtitle + one visual.
