# 工作记忆

这里补齐历史资料和文档审查的两层入口：[保留记录目录](session-logs/)和[整理索引](index.md)。根目录已有 review、`docs/` 中的审查与 verification 文件仍保留原路径，通过索引引用。持续任务的归档与生成索引遵循项目的 `docs/work-memory/` 入口；本目录不是另一套采集工具。

## 原始层

本目录保留 `session-logs/YYYY-MM-DD-topic.md` 格式的既有笔记与本轮审查记录。保留可获得的原始用户需求、基线、可核验的操作、结果和证据；明确是否包含完整对话。已有原始 review 文件不改写为当前结论。发现错误时追加更正，并链接最新契约。新任务按项目工作记忆入口使用相应模板，不在两处复制完整摘要。

完整对话或工具输出未被保存时必须写明缺口；任务摘要不能标为完整原始对话。对敏感内容采用明确脱敏标记，不收录环境变量值、密钥、票据和个人账户数据。细则见[文档体系](../docs/documentation-system.md)。

## 整理层

`index.md` 先列当前主题、接手入口和未完成项，再列历史来源。在这些资料被更正、替代或交接时更新，并纳入项目定期整理。可以重写索引来压缩内容，但不能因此删除原始证据。本次没有为这个目录单独创建后台调度。

## 恢复工作

1. 从索引找到主题，先读当前 Reference 和相关 ADR。
2. 打开链接的原始记录，核对其日期、提交范围、已执行验证和限制。
3. 对照当前代码确认结论是否仍成立，再做修改；历史“通过”不能当作当前提交通过。
4. 本次收尾追加记录并更新索引。稳定约束才进入 `AGENTS.md`。

`docs/memory-management.md` 讨论 React 内存与泄漏，和这里的工作记忆体系是两个主题。
