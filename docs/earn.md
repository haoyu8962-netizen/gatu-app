# Earn：借贷储备池页面

- 状态：已实施，2026-09-27；尚未发布。存入与 Max 全部取出已在用户自己的主网账户实测通过；借入与偿还未做真实测试。
- 决策与取舍：[ADR 0020](adr/0020-earn-borrow-lend-page.md)。关联：[确认面契约](confirmation-surfaces.md)、[资金类弹层的结果反馈](funds-dialog-outcome-plan.md)、[Runtime guardrails §11](runtime-guardrails.md#11-desktop-top-navigation)、[ADR 0013](adr/0013-desktop-navigation-collapse.md)。
- 代码：`apps/terminal/src/domain/earn.ts`、`domain/earn-submission.ts`、`hooks/earn/use-earn-data.ts`、`components/earn/`、`routes/earn.tsx`。

## 目标

`/earn` 对齐官方终端 `app.hyperliquid.xyz/earn`：在 HyperCore 借贷储备池里存入（Supply）、取出（Withdraw）、借入（Borrow）和偿还（Repay）。官方文档把它叫做 Earn（HLP 的说明写 HLP "supplies USDC in Earn"），与组合保证金、手动借款是同一套储备池。页面不汇总 HLP 金库或 HYPE 质押，这两者仍在 `/vaults` 与 `/staking`。

## 依据与核对方式

实现以三处来源为准，冲突时按项目契约取舍并写入 ADR 0020：

| 来源 | 用到的内容 |
| --- | --- |
| 官方文档（hyperliquid-docs MCP） | `borrowLendUserState`、`borrowLendReserveState`、`allBorrowLendReserveStates`、`userAbstraction` 的请求与返回；LTV、健康因子、部分清算阈值 `(1+LTV)/2`、利率模型、账户模式与组合保证金规则 |
| SDK `@nktkas/hyperliquid` 0.33.3（仓库锁定版本） | `borrowLend({ operation, token, amount })` 的参数校验（`amount` 为无符号小数字符串或 `null`）、L1 action 签名；`userBorrowLendInterest({ user, startTime, endTime? })`；账本 `borrowLend` 类型。该版本没有 `userBorrowLendInterest` 订阅 |
| 官方终端（2026-09-27 只读取证：页面脚本 `BorrowLendPage-*.js` 与 `config-*.js`、公开 info 接口） | 页面结构、文案、Max 规则、按钮禁用条件、清算价公式、Agent 签名、组合保证金下的行为、USDH 的显示规则、资产 ID |

取证只读取了公开脚本与公开接口，没有在官方终端提交任何操作。

资产列表由储备池条目对照 `spotMeta` 生成，不写死 ID：主网为 USDC 0、HYPE 150、UBTC 197（显示 BTC）、USDT0 268（显示 USDT）、USDH 360；测试网的 HYPE 是 1105，还有其他条目。以下情况整张快照不可用（失败关闭）：储备池里有、`spotMeta` 里找不到的资产；储备池或用户仓位里出现重复的资产 ID；用户在某资产上有非零存入或借出，但储备池里没有这个资产（否则会漏算债务、多算可借额度）。接口返回在 `parseEarnReserves` / `parseEarnUserState` / `parseEarnInterest` 里逐字段校验，参与计算的金额、价格、利率与 LTV 缺失或格式不对时按不可用处理。只用于展示或未使用的字段放宽：`utilization` 缺失时记为空（目前既不参与计算也不显示；给出了但非法仍整张作废），`healthFactor` 缺失按 `null` 处理，只影响健康因子的显示。SDK 把前者标为必填、后者为可空。

## 计算（`domain/earn.ts`，全部 Big.js）

- **抵押品与计息资产。** `ltv > 0` 为抵押品（HYPE、BTC），存入不计息，表里利息列显示 N/A；`ltv = 0` 为计息资产（USDC、USDT、USDH），也是唯一可借的资产。
- **USDH。** 只有持有存入或借出时才出现在表里，也不出现在存入的资产选择里（官方同样处理）。
- **汇总。** 总存入 = Σ 存入 × 预言机价；LTV 加权存入 = Σ 存入 × 预言机价 × LTV；总借出 = Σ 借出 × 预言机价；可借额度 = max(0, LTV 加权存入 − 总借出)。
- **健康因子。** 直接显示接口的 `healthFactor`，上限 1000%；没有借款时显示 `--`。
- **已赚利息 / 应付利息。** `value − basis`。
- **清算价（标准账户）。** 阈值系数 Z(LTV)：LTV ≥ 0.5 时为 (1+LTV)/2，否则为 2·LTV/(1+LTV)。对资产 t：价 = (其他借款价值 − 其他资产阈值价值) / (存入ₜ × Z − 借入ₜ)，结果 ≤ 0 或高于当前预言机价时不显示。与官方文档的部分清算阈值（HYPE 82.5%、BTC 75%）一致。
- **清算价（组合保证金）。** 预言机价 × (1 − 维持后可用额 / 现货总额)。
- **Max。**

| 操作 | Max |
| --- | --- |
| 存入 | 现货可动用余额：min(总额 − 冻结, 维持保证金后可用额) |
| 取出计息资产 | min(已存入, 储备池流动性 `balance`) |
| 取出抵押品 | min(已存入, 可借额度 / (预言机价 × LTV), 储备池流动性) |
| 借入 | min(可借额度 / 预言机价, 储备池流动性) |
| 偿还 | min(已借入 + 10^-weiDecimals, 现货可用余额) |

  Max 向下取整到该资产的 `weiDecimals`，输入框也限制到这个精度。预言机价格为 0 时，取出抵押品和借入的 Max 为不可用（不做除法），弹窗不能提交；账户在某个价格为 0 的资产上有存入或借出时整张快照不可用，因为它的估值会被算成 0，从而多算其他资产的可取额度。
- **与官方的差异。** 官方的 Max 不考虑储备池流动性，也直接用维持保证金后可用额；这里取更保守的值：官方文档说明利用率达到 100% 时存入者无法取出，`balance` 约等于总存入 − 总借出；“维持保证金后可用额”是交易购买力，可能大于未冻结的现货余额。

## 页面

- 标题、官方说明（组合保证金账户显示另一段说明）、四个操作按钮。
- 三张统计卡：健康因子（悬浮说明官方定义）、总存入、总借出。
- 三个页签：存入与借入（两张表；1000px 及以下为卡片）、利息、操作历史。
- 存入表列：资产、LTV、APY、预言机价格、清算价、你的存入、你的已赚利息（组合保证金账户隐藏）、总存入、操作。借入表列：资产、LTV（N/A）、APY、预言机价格、你的借入、你的应付利息（组合保证金账户隐藏）、总借出、操作。
- APY 直接显示 `yearlyRate × 100`，与官方一致；字段名叫 YearlyRate，官方文档的利率是连续复利年化，页面沿用官方的“APY”称呼。
- 被动加载不显示加载或错误文字，只用 `aria-busy`；个人数值未就绪或未连接时在展示层显示格式化的零（统计卡桌面 `$0.00`、手机 `$0`，表格 `0.00 USDC`、`0.00000 BTC`，与官方一致），健康因子没有借款时为 `--`。这是[数据展示契约](mobile-data-presentation.md)第一张表“账户数值未就绪”一行允许的形式：零只用于展示，不进入计算、门控或“没有借款”这类结论。未连接钱包时表格照常显示公开数据，操作禁用；连接入口在页头。

## 操作可用性

按钮的禁用条件对齐官方：

| 操作 | 禁用条件 | 说明文案 |
| --- | --- | --- |
| 存入 | 组合保证金；数据未就绪；行内另要求该资产现货余额 > 0 且不是 USDH | 组合保证金说明 |
| 取出 | 组合保证金；没有任何存入 | You have no supplied assets to withdraw. |
| 借入 | 组合保证金；没有存入抵押品 | Supply a supported collateral asset to borrow. |
| 偿还 | 没有借款；组合保证金（偏差，见下） | You have no borrows to repay. |

在此之上叠加项目的资金动作门控（`useFundsActionAvailability`）：地区受限或无法判定、手机上的 Agent-only 会话（显示唯一的“需要桌面主钱包”原因）、没有钱包访问、账户模式未知或不支持、账户数据未就绪、储备池数据刷新失败（即使还有缓存）时全部禁用。地区受限与 Agent-only 的原因显示在页头说明下方和弹窗顶部；其他情况只禁用，不显示文字。数据未就绪时弹窗不计算 Max，也不给出“余额不足”。

禁用但有原因的按钮保持可聚焦（页头按钮用 `focusableWhenDisabled`，行内操作用 `aria-disabled`），原因同时放在悬浮提示和 `aria-describedby` 指向的屏幕阅读器文字里。手机上页头与卡片按钮高度至少 44px，健康因子说明触发器有按压反馈。

## 提交

1. 同步 ref 防重复点击；弹窗在请求期间不可关闭，确认按钮名固定为操作动词（Supply / Withdraw / Borrow / Repay），不显示进度。
2. 确认按钮是 `TradingActionButton`（`requiresBuilderFee={false}`）：签名方未就绪时先换成“启用交易”，与官方在确认按钮外包一层交易前置状态的做法一致。借贷不需要 builder fee。
3. `useExchange("borrowLend")` 走交易签名方：邮箱账户用自己的嵌入式钱包，外部钱包用已验证的 Agent。`borrowLend` 已加入跨标签页资金锁。执行顺序：拿到资金锁 → `useExchange` 强制刷新法律条款校验 → 签名会话锁内运行 Earn 的锁内守卫（ADR 0020 D12）：并行复核账户模式（`useAccountAbstractionPreExecutionGuard`）、地区（强制刷新）、储备池与用户仓位（`fetchFreshEarnState`：直接请求 info 接口并传入守卫的中止信号，请求前后取消页面上进行中的同名查询，结果写回缓存；不依赖页面查询 `refetch` 的返回值，它被连续取消时可能返回旧缓存且不带错误），用最新数据重算 Max，发送数量必须 ≤ 弹窗展示的 Max 且 ≤ 最新 Max，全额请求还要求本金一致且仍可全额，否则失败关闭并提示“收益余额已变化”；存入与偿还还校验现货余额的新鲜度（`assertFreshFundsAmount`）。复核在锁内而且是新请求，所以本浏览器其他标签页先完成的资金动作只要已经反映在 info 接口里就会被看到；交易所返回之后 info 接口是否立即一致没有验证。从等资金锁开始到签名发出，同一交易客户端上排队的其他请求（包括下单，以及撤单、只减仓等优先请求）都要等待：等资金锁最长 10 秒，守卫本身最长 10 秒，法律校验（含重试）、等会话锁与签名发送没有统一的总时限（ADR 0020 D12）。
4. SDK 边界的同步守卫（`verifyEarnSubmissionAtBoundary`）：入队时只核对身份、交易生命周期和参数；到边界时要求锁内复核已完成且不超过 20 秒（`EARN_VERIFICATION_TTL_MS`）、账户快照仍就绪、不是组合保证金，并用锁内快照与本页最新缓存分别重算 Max、校验本金。
5. 存入与借入总是发送精确的小数字符串。取出或偿还时，点 Max 那一刻可以全额（不受抵押要求、池流动性或现货余额限制）才记为全额意图并发送 `amount: null`；点 Max 时受限的始终按显示数量提交，限制之后解除也不会自动变成全额。全额意图绑定账户所有者与网络、操作、资产和本金 `basis`；由完整的新数据证实本金变化或全额不再可行时，意图永久作废并提示重新点 Max（之后即使恢复原值也不会自动生效）；判断时从未按操作过滤的完整快照里找这个资产，所以偿还时借款已经还清、偿还列表里不再有它，也算作废；数据暂时无法核验（刷新失败、账户模式短暂未知）时只禁用提交、不显示提示，草稿保留。修改数量、切换资产、切换账户所有者或网络都会清掉它；账户模式短暂变化不会清空草稿。弹窗写明“在执行时取出全部存款 / 偿还全部借款，含已产生的利息”。锁内复核与 SDK 边界都校验本金一致，但交易所请求里没有本金条件：锁内复核之后的签名与传输期间，若这个仓位被别处改变（同一账户在其他客户端的操作、Agent/API 钱包、清算），交易所按执行时的全额处理（取出多出的回到自己的现货；偿还多扣的现货用于偿还新增借款）。这是记录在案的契约例外，见 ADR 0020 D2。全额偿还要求现货至少覆盖借款加一小时利息。
   交易所要求存入余额为 0 或至少 $1（来自交易所报错 `Minimum amount supplied is $1`，官方文档未写）。手动输入的取出会让余额低于 $1、或存入后余额低于 $1 时，弹窗禁止提交并提示改用 Max 或至少保留 $1；这条报错仍从交易所返回时，显示翻译后的说明。
6. 请求结束后关闭弹窗，结果走全局通知：成功为 `Supplied USDC` 等并附数量；交易所拒绝或核验失败为错误通知；传输层结果不明为常驻警告，提示先查看操作历史再重试。通知内容是 `EarnOutcomeToastContent`：渲染时订阅语言和数字格式，并记下发起时的网络与账户；当前网络或账户与之不同时立即撤下该通知（包括常驻警告），不会把旧账户的结果显示给新账户。
7. 弹窗打开后（或切换资产后）记下该资产存入与借出的本金 `basis`；之后本金变化时（存入、取出、借入、偿还，包括在另一个窗口或终端里做的），在摘要下方的 `aria-live="polite"` 区域提示“打开此窗口后你的仓位已变化”，只在弹窗打开且可编辑时显示（请求进行中与关闭动画期间都不显示，全额意图作废的提示同样如此），不影响提交（确认面契约第 4 条）。本金取自完整快照，借款还清后该资产不在偿还列表里，提示照样出现。利息累积只改变 `value`、不改变 `basis`，不会触发这条提示。2026-09-27 真实账户测试发现：最初比较的是 `value`，它随利息持续增长，弹窗打开几秒后就会误报。
8. 每次打开弹窗使用新的会话 ID 作为 key，关闭只把 `open` 置为 false，退出动画可以播完；关闭中的弹窗禁用确认。数量错误通过 `aria-describedby` 关联到输入框。

## 与官方的偏差

| 偏差 | 原因 |
| --- | --- |
| 存入与借入的 Max 发送精确数量，不发 `null`；取出与偿还的 Max 在可全额时与官方一样发 `null` | 确认面契约要求执行不超过用户看到的值；取出和偿还的全额在锁内复核后仍有签名与传输的窗口，多出的部分回到自己的现货或用于偿还同一账户的新增借款（2026-09-27 修订，原先所有 Max 都发精确数量，导致全部取出被 $1 下限拒绝） |
| 组合保证金账户不能在 Earn 页偿还 | 官方在组合保证金下的偿还是卖出抵押品换成债务币再还的现货兑换流程，第一版没有实现；按钮禁用并说明原因。组合保证金的开通在本项目仍受 `PORTFOLIO_MARGIN_FEATURES` 门控 |
| 利息页签轮询 info 接口，不是 WebSocket 推送 | 锁定的 SDK 0.33.3 没有 `userBorrowLendInterest` 订阅 |
| 操作历史来自共享账本的 30 天窗口，Earn 记录单独保留，最多 200 条 | 复用已有的分页、校验与订阅合并；官方最多显示 30 条 |
| 结果未知没有持久化标记与恢复入口 | 金库/质押的标记机制绑定其对账数据源；Earn 第一版只给常驻警告并提示查看历史 |
| Max 受储备池流动性限制，存入/偿还按未冻结且维持保证金后仍可用的较小值 | 官方不考虑这两点；利用率 100% 时存入者无法取出，维持保证金后可用额是交易购买力，不等于可动用现货 |
| 地区受限时四个操作都禁用 | 与官方一致（官方的交易状态门控在 IP 受限时禁用全部操作）；也符合本项目地区门控拦截资金动作的规则 |
