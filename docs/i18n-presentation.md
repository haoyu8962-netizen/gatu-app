# Runtime localization

Terminal language changes must update visible text, tooltips and accessible names without reloading the page, remounting panels or resetting user input. Apply these rules before changing localized presentation.

- React components and hooks that render translated text normally use `useLingui` or `Trans` from `@lingui/react/macro`. When a helper requires a reactive translation function, use the public `useLingui` hook from `@lingui/react` and its `_` function with `msg` descriptors from `@lingui/core/macro`. The macro hook exposes `t`, not `_`; do not combine two locale subscriptions or assert past that API difference. A core translation call alone does not subscribe its component to locale changes.
- A translation helper called during rendering must receive its translated label or reactive translation dependency explicitly. React Compiler may retain a helper result when its arguments do not change; reading the global locale inside the helper does not make that dependency visible.
- Do not hide a global `t` or `i18n._` lookup in a presentation helper's default parameter. Require the translated labels or reactive translator at every call site, including nested confirmation-row helpers. TWAP stop-price labels must follow the current locale in forms, mobile summaries and confirmation dialogs while retaining their semantic buy/sell side and entered prices.
- A helper that translates takes the descriptor-only `Translate` type from `apps/terminal/src/lib/translate.ts` and builds its messages with `msg`. Never pass the macro `t` from `useLingui()` into a helper and call it as a tagged template: the macro only rewrites tagged templates inside the component that called `useLingui()`, so the helper returns an empty string at runtime and the message never reaches the catalogs. `lingui-helper-translator-contract.test.ts` rejects the `ReturnType<typeof useLingui>` type, tagged templates on any function parameter (whatever its name, including renamed destructuring such as `{ t: translate }` and tags behind parentheses or a type assertion) unless the parameter is declared as a template tag function taking a `TemplateStringsArray`, and `.t` or `._` property tags.
- Error text that stays visible (notification tasks, component state, inline alerts) stores the classified failure, not a translated or raw string, and is translated when rendered. Exchange rejection texts are translated only when known and otherwise shown exactly as sent; our own, SDK, network and wallet errors are never shown raw ([ADR 0024](adr/0024-translate-action-errors-at-render.md)). Throw `LocalizedActionError` with a `msg` descriptor for a message the user should see.
- Keep protocol values such as `Alo`, `Gtc` and `Ioc` separate from their displayed labels. A language switch must not change order values, selected options, wallet identity, routes or theme preferences.
- Pending confirmation drafts retain semantic values such as market kind and order side, not translated side text. Derive the confirmation side row and CTA from those values in the active locale while preserving the draft and submission payload.
- Inspect the existing locale catalog before adding translations. If the translation exists but remains in the previous language, repair the render dependency instead of duplicating strings or forcing remounts.
- Include `aria-label`, `title` and hidden accessible descriptions in localization checks. Theme controls describe the action for the current theme in the active language.
- Name the product only through the `BRAND_NAME` constant (`apps/terminal/src/config/brand.ts`, read from `brand/brand.json`): write `<Trans>Install {BRAND_NAME}</Trans>` or ``t`… ${BRAND_NAME} …` ``, so every catalog keeps the `{BRAND_NAME}` placeholder and a later rename changes no message ID or translation. Translations keep the placeholder exactly as often as the source message; `brand-catalog-contract.test.ts` rejects literal product names (`sairn`, `sairn`, `hyperterminal`) in active messages and translations.
- Chinese wording follows the controls it describes. Funds buttons, labels, titles, nouns and notifications say 存款 and 提款, never 充值, 提现 or 入金; a verb with an object keeps 存入 or 提取 (向 Hyperliquid 存入 USDC, 提取金库权益, 提取抵押品). Earn's Supply is its own concept (存入借贷), so its 存入 labels stay. Order results say 委托, cancellations 取消 and TWAP 终止, like the Open Orders tab and the Cancel and Terminate buttons.

Regression tests switch an already mounted surface from English to Chinese and back, preserving the same interactive DOM nodes and selected values. Cover TIF chips and selectors, a fixed order-confirmation draft, disconnected position text and theme-control accessible names. Confirmation rows receive the reactive translation function explicitly so a stable draft cannot retain its old order type or TIF labels. Check the Chinese catalog entries used by these tests so a synthetic test catalog cannot conceal missing production translations. Validate the actual terminal after switching language while leaving the current route and order form intact.

The [Lingui React API](https://lingui.dev/ref/react#uselingui) explains that context consumers rerender when locales or catalogs change and that the reactive `_` reference changes with those updates; the macro hook exposes the equivalent reactive `t`. [Lazy translations](https://lingui.dev/guides/lazy-translations) keep message descriptors separate from the moment they are rendered. The [installed 5.7.0 provider implementation](https://github.com/lingui/js-lingui/blob/v5.7.0/packages/react/src/I18nProvider.tsx) confirms this context behavior; applying it does not require changing the dependency version or provider hierarchy.
