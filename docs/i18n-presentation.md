# Runtime localization

Terminal language changes must update visible text, tooltips and accessible names without reloading the page, remounting panels or resetting user input. Apply these rules before changing localized presentation.

- React components and hooks that render translated text normally use `useLingui` or `Trans` from `@lingui/react/macro`. When a helper requires a reactive translation function, use the public `useLingui` hook from `@lingui/react` and its `_` function with `msg` descriptors from `@lingui/core/macro`. The macro hook exposes `t`, not `_`; do not combine two locale subscriptions or assert past that API difference. A core translation call alone does not subscribe its component to locale changes.
- A translation helper called during rendering must receive its translated label or reactive translation dependency explicitly. React Compiler may retain a helper result when its arguments do not change; reading the global locale inside the helper does not make that dependency visible.
- Read `i18n.locale` into a local before a branch or a render-time callback uses it. React Compiler keeps the property path `i18n.locale` as a memo dependency only when the memoized computation reads it unconditionally. When the value comes from a conditional expression (`?:`, `&&`, `||`, `??`, JSX branches included), from a callback that runs during render (`map` and the other array methods), or is built across a branch (for example items pushed inside an `if` in a loop), a read that happens only there is recorded as the base `i18n` object, which stays the same Lingui instance across a language switch, so the cached result keeps the previous language. Write `const locale = i18n.locale;` and pass `locale`, as the footer clock (`footer-bar.test.tsx`) and the Vault list's fetched time (`vaults-view.test.tsx`) do; this is always safe. Effect callbacks, lazy state initializers, JSX event handlers and `ref` callbacks, and the `queryFn`, `mutationFn`, `buildRows` (the CSV row builders the history export hooks call after their requests settle) and `on*` options passed to a hook read the locale when they run rather than from a cached render result, so they may read `i18n.locale` directly; any other callback handed to a hook (a custom hook may call it during render) and any other function nested in a component, including a handler declared with a name, uses the local `locale`. Observed in `babel-plugin-react-compiler` 1.0.0 output on 2026-10-02; a plain `if` statement whose memo scope sits inside the branch kept `i18n.locale`, but whether a branch read is safe depends on where the compiler places its memo scopes, so `i18n-reactivity-contract.test.ts` rejects reads of the locale from Lingui's i18n object (written `i18n.locale` or `i18n["locale"]`, behind a type assertion, or destructured as `const { locale } = i18n`; the object is followed by binding through imports and their aliases, `const` aliases, destructuring including defaults and parameter defaults, conditional and logical expressions, objects built from literals and carried through those same aliases, destructuring and choices up to four levels of nesting, where object members and function returns share that budget (a later member replaces an earlier one, and a spread copies the members it is known to carry, such as the `i18n` of a `useLingui()` result), `useLingui()` calls, functions in the same file that return it, called by name, through an alias or as an object method or getter, and any hook's result, which may be the i18n object or a context carrying it, so that errs strict; a same-named variable elsewhere in the file does not interfere. It is not followed through other function arguments, calls through `call`, `apply` or `bind`, state, refs, reassigned variables, other containers, a non-hook function from another module, or any other data flow not listed here: the contract is a lexical guard for these shapes, not a proof, and reading `const locale = i18n.locale;` at the top of the component remains the only always-safe form. The analysis only ever adds what a value may hold, so a closure or function that reads a binding declared further down can keep a Lingui role that a later override removes at run time; that errs strict, never loose) in a branch (including logical assignments and destructuring defaults), a loop body, an optional call or a nested function other than those kinds in every component and hook; an unconditional read directly inside a `useMemo` callback is allowed. It recognizes components and hooks with the same rules as the number-format contract (`src/lib/tests/harness/react-source.ts`), a superset of React Compiler's own inference: by the name of the function or of the variable, assignment target, object or class property or destructuring default that receives it, any callback of `memo` or `forwardRef` (also written `React.memo` or `React[memo]`) whatever its own name, any function that opts in with `"use memo"`, an anonymous default export in a `.tsx` module and a route's component option written as a function or a method.
- A dependency array does not make React Compiler recompute. The compiler takes the dependencies of a `useMemo` or `useCallback` from what the callback reads and drops entries the callback never reads, so `i18n.locale` listed beside a callback whose helpers read the global locale recomputes nothing after a switch. Pass the values into the computation, as the funding history chart ([number format rule 7](number-format-setting.md)) and the portfolio performance chart (`portfolio-performance-chart.test.tsx`) do; `i18n-reactivity-contract.test.ts` rejects `useMemo` and `useCallback` dependencies the callback does not read. It reads callbacks written inline (also parenthesized or asserted) or declared by name in a scope the call sees, and follows React hooks imported under another name; other callbacks are skipped. A parameter or local of the callback that shadows a dependency's name does not read it, types are not reads, and destructuring defaults and computed keys inside the callback are. A read path counts whether it is written with dots, a static key or an assertion, or destructured, and a `const` alias of a path (`const intl = i18n`, `const { locale = "en" } = i18n`) stands for that path in both the callback and the dependency list, wherever it is declared, including when deciding whether a dependency sits below Lingui's i18n object; a value that is only dropped (`void locale`) is not read. Reading an object counts as reading its properties, except for Lingui's i18n object (also reached as `lingui.i18n`, and assumed for any hook's result, which may be that object), which keeps its identity across a switch: a dependency such as `i18n.locale` counts only when the callback reads that path itself. Locale reads, destructured `locale` bindings and this dependency rule all ask the same question of a value, so they treat a hook's result alike. Fixing the array does not mean deleting the `useMemo`: the one in `PortfolioPerformanceChart` stays because without it the compiled output no longer memoizes `buildChart` (118 cache slots fall to 43) and every pointer move would rebuild the chart model.
- The date and list formatters in `lib/format.ts` (`formatDateTime`, `formatDateTimeShort`, `formatTime`, `formatList`) read the global locale when no `locale` option is given, so a render-time call without it is cached by its other arguments and keeps the previous language. Components and hooks pass a `locale` option to every call, as the referral histories, staking tables and open-orders row do (`referral-history-locale.test.tsx`, `staking-view.test.tsx`, `desktop-orders-cancel-all.test.tsx`). During render that is `const locale = i18n.locale;` read as above; an effect callback or inline JSX event handler may instead read `i18n.locale` when it runs, as the previous rule allows, which suits a callback that outlives its render. A call that shares its cache slot with `_t` or a translator built from it, or sits in a function the compiler does not compile, shows the new language by accident; do not rely on that. The rule also covers effects, event handlers and CSV export columns, like the number formatters (ADR 0036): a CSV row builder (`buildRows`) runs only after the export's requests settle, so it reads `i18n.locale` then, at the same moment its headers and labels are translated with `t`, and a language switch during an export cannot mix languages in one file (`desktop-history-exports.test.tsx`, `history-csv-twap.test.tsx`); an effect that formats a date with the render-time `locale` lists it and runs again after a switch. A module-level helper that formats during render takes the locale as a parameter and passes it on (`formatFundingChartAxisLabels(model, range, locale, numberFormat)`). `date-locale-reactivity-contract.test.ts` enforces this at the source level: inside a component or hook, every reference to one of these formatters or to an alias of one must be a call whose options object literal has a `locale` property; components and hooks may not reference a module-level declaration that calls one without it (followed across modules, re-exports, aliases and namespace imports); a call at module scope without it is rejected; and every `lib/format.ts` export that reads the interface language must be on the contract's list. The contract checks that a `locale` is written, not where its value comes from or whether a later spread replaces it: a helper whose `locale` parameter is optional or has a default (`processTrades`) still relies on its caller passing one, and namespace re-exports (`export * as`) are not followed. It recognizes components and hooks, and resolves module-level names, with the same harness as `number-format-reactivity-contract` (`src/lib/tests/harness/react-source.ts` and `module-graph.ts`), so it shares that contract's superset of React Compiler inference and its module-graph limits (ADR 0036, decision 6). A namespace import destructured inside a function (`const { formatDateTime: when } = format`) takes each named export out as a value, like `const when = format.formatDateTime`; a formatter, an alias of one or a helper that reads the language is flagged even when every later call passes a `locale`. A name destructured with a default, or through a nested pattern, may hold something other than the formatter, so the contract treats it as its own declaration and flags it even when the call passes a `locale`; that errs strict. The self-check follows reads of `i18n` from `@lingui/core`, imported by name or as a namespace member (`lingui.i18n`, `lingui["i18n"]`), through the module's own functions, classes and variables, and reads every export of `lib/format.ts`, whether written on a function, class or variable declaration (destructured or not), in an export list (renamed or not) or as the default export (named or anonymous), but not a name `lib/format.ts` re-exports from another module; a destructured export takes its whole initializer as its source, so every name in it counts once any part reads the language, which errs strict. Like `i18n-reactivity-contract`, the contract is a lexical guard for the shapes listed here, not a data-flow proof: a formatter or a namespace handed whole to another function, kept in state, a ref or another container, or reassigned is not followed. Passing `{ locale }` read from `const locale = i18n.locale;` at every call stays the always-safe form, and this boundary does not excuse a gap in a shape listed above.
- Numbers follow the same mechanism with a different dependency: components and hooks take their number formatters from `useNumberFormat()` and pass them to helpers ([number format rule 9](number-format-setting.md), [ADR 0036](adr/0036-render-time-number-formatters.md)); `number-format-reactivity-contract.test.ts` enforces it.
- Do not hide a global `t` or `i18n._` lookup in a presentation helper's default parameter. Require the translated labels or reactive translator at every call site, including nested confirmation-row helpers. TWAP stop-price labels must follow the current locale in forms, mobile summaries and confirmation dialogs while retaining their semantic buy/sell side and entered prices.
- A helper that translates takes the descriptor-only `Translate` type from `apps/terminal/src/lib/translate.ts` and builds its messages with `msg`. Never pass the macro `t` from `useLingui()` into a helper and call it as a tagged template: the macro only rewrites tagged templates inside the component that called `useLingui()`, so the helper returns an empty string at runtime and the message never reaches the catalogs. `lingui-helper-translator-contract.test.ts` rejects the `ReturnType<typeof useLingui>` type, tagged templates on any function parameter (whatever its name, including renamed destructuring such as `{ t: translate }` and tags behind parentheses or a type assertion) unless the parameter is declared as a template tag function taking a `TemplateStringsArray`, and `.t` or `._` property tags.
- Error text that stays visible (notification tasks, component state, inline alerts) stores the classified failure, not a translated or raw string, and is translated when rendered. Exchange rejection texts are translated only when known and otherwise shown exactly as sent; our own, SDK, network and wallet errors are never shown raw ([ADR 0024](adr/0024-translate-action-errors-at-render.md)). Throw `LocalizedActionError` with a `msg` descriptor for a message the user should see.
- Keep protocol values such as `Alo`, `Gtc` and `Ioc` separate from their displayed labels. A language switch must not change order values, selected options, wallet identity, routes or theme preferences.
- Pending confirmation drafts retain semantic values such as market kind and order side, not translated side text. Derive the confirmation side row and CTA from those values in the active locale while preserving the draft and submission payload.
- Inspect the existing locale catalog before adding translations. If the translation exists but remains in the previous language, repair the render dependency instead of duplicating strings or forcing remounts.
- Include `aria-label`, `title` and hidden accessible descriptions in localization checks. Theme controls describe the action for the current theme in the active language.
- Name the product only through the `BRAND_NAME` constant (`apps/terminal/src/config/brand.ts`, read from `brand/brand.json`): write `<Trans>Install {BRAND_NAME}</Trans>` or ``t`… ${BRAND_NAME} …` ``, so every catalog keeps the `{BRAND_NAME}` placeholder and a later rename changes no message ID or translation. Translations keep the placeholder exactly as often as the source message; `brand-catalog-contract.test.ts` rejects literal product names (`gatu`, `sairn`, `hyperterminal`) in active messages and translations.
- Chinese wording follows the controls it describes. Funds buttons, labels, titles, nouns and notifications say 存款 and 提款, never 充值, 提现 or 入金; a verb with an object keeps 存入 or 提取 (向 Hyperliquid 存入 USDC, 提取金库权益, 提取抵押品). Earn's Supply is its own concept (存入借贷), so its 存入 labels stay. Order results say 委托, cancellations 取消 and TWAP 终止, like the Open Orders tab and the Cancel and Terminate buttons.

Regression tests switch an already mounted surface from English to Chinese and back, preserving the same interactive DOM nodes and selected values. Cover TIF chips and selectors, a fixed order-confirmation draft, disconnected position text and theme-control accessible names. Confirmation rows receive the reactive translation function explicitly so a stable draft cannot retain its old order type or TIF labels. Check the Chinese catalog entries used by these tests so a synthetic test catalog cannot conceal missing production translations. Validate the actual terminal after switching language while leaving the current route and order form intact.

The [Lingui React API](https://lingui.dev/ref/react#uselingui) explains that context consumers rerender when locales or catalogs change and that the reactive `_` reference changes with those updates; the macro hook exposes the equivalent reactive `t`. [Lazy translations](https://lingui.dev/guides/lazy-translations) keep message descriptors separate from the moment they are rendered. The [installed 5.7.0 provider implementation](https://github.com/lingui/js-lingui/blob/v5.7.0/packages/react/src/I18nProvider.tsx) confirms this context behavior; applying it does not require changing the dependency version or provider hierarchy.
