# ADR 0007：内容安全策略分两步收紧

- 状态：已接受（2026-09-14）；report-only 头已于同日开启（`edge-config.json` 的 `cspReportUri` 指向接收器的函数 URL，两条分发的 viewer-response 函数已发布）；第二步（内联脚本哈希，决策 5）同日先以 report-only 发布、随后切到 `enforce`；`img-src` 收窄（决策 6）同日切到 `enforce`。两条分发的主文档策略现在是：`script-src` 只有 `'self'`、Turnstile 主机与内联脚本哈希，`img-src` 只有已知主机；候选策略与强制策略相同，report-only 头不再下发
- 前置：[ADR 0005](0005-spa-static-shell.md)（CSP 由 viewer-response 函数下发）、[ADR 0006](0006-startup-preloads-and-edge-caching.md)

## 背景与约束

主文档策略的 `script-src` 与 `style-src` 含 `'unsafe-inline'`，`img-src` 放行任意 `https:`，`script-src` 还带应用代码并不使用的 `blob:`。官方站完全没有 CSP，所以这是收紧空间而不是退步，但收紧不能靠猜：内联脚本有三段（主题引导、TanStack 的流屏障、每页一段 `$R[n]` 恢复脚本），图片来源涉及 Privy、WalletConnect、Coinbase 等第三方。约束：CloudFront 的 Lambda 源用 OAC 签名，浏览器自动发出的 CSP 报告不带 `x-amz-content-sha256`，进不了签名源；CloudFront Functions 拿不到请求体；静态托管没有 nonce。

## 决策

1. **候选策略先以 report-only 观察。** `security-headers.ts` 新增 `cspReportOnlyDirectives`：`img-src` 收窄为 `'self' data: blob:` 加 `app.hyperliquid.xyz`、`*.privy.io`、`explorer-api.walletconnect.com`、`*.walletconnect.com`、`*.coinbase.com`，`script-src` 去掉 `blob:`；其余与现行策略相同。viewer-response 函数在非图表路径上把它作为 `Content-Security-Policy-Report-Only` 下发，附 `report-uri`。现行 `Content-Security-Policy` 不变。
2. **报告接收器独立于签名源。** 新增 Lambda `gatu-terminal-api-csp-report`（128 MB、3 s、`AuthType=NONE` 的函数 URL，资源策略须同时授予 `*` 两条语句：`lambda:InvokeFunctionUrl` 与带 `lambda:InvokedViaFunctionUrl` 条件的 `lambda:InvokeFunction`；预留并发因账号并发下限暂未设置），处理器 `src/edge/csp-report-lambda.ts` 无任何依赖：只接受 `POST` 与 CSP 报告的三种内容类型，正文 ≤ 8 KB，每实例每分钟 120 条（2026-09-15 起按写出的报告条数而不是请求数扣减预算，每请求最多 10 条，缺少必需字段的空报告丢弃，预算不足回 429），解析旧格式 `{"csp-report"}` 与 Reporting API 批次后把裁剪过的摘要写进 CloudWatch，返回 204。摘要里的 `document-uri`、`blocked-uri`、`source-file` 只保留 origin 与路径（去掉查询串、凭据与片段，`/join/<code>` 折叠为 `/join/*`，非 URL 的值如 `inline`、`eval` 原样保留），脚本样本截到 40 字符，因此推荐码与带个人信息的查询参数不会进入日志。它不持有密钥、不写存储，被滥用的上限是日志量。
3. **接收器地址是部署配置。** `deploy/cloudfront/edge-config.json` 的 `cspReportUri` 由 `render-functions.mjs` 读取；为空时函数不发 report-only 头，`pnpm test:cloudfront` 的漂移检查保证提交的函数代码与配置一致。`deploy.mjs functions` 从文件更新并发布两个 CloudFront Functions。
4. **收紧的门槛。** `script-src`：report-only 一个发布周期内没有 `blocked-uri: inline` 的报告（现行策略早已拦截的 `eval` 除外）、脚本化覆盖（双端、文档页、`/join`、钱包登录、Turnstile、下单、充值、图表）无报告后，把 `edge-config.json` 的 `cspScriptHashes` 切到 `enforce`（2026-09-14 用户决定当日切换：正式域名未切、没有真实流量，依据只有脚本化覆盖与接收器日志，未等满一个发布周期）；`img-src` 收窄原定等正式域名切换后有真实流量再决定，因为第三方图片来源无法从代码穷举；2026-09-14 用户决定当日切换，依据是代码扫描（应用自身只用 `app.hyperliquid.xyz/coins` 的代币图标、本地 `/coins/USDC.svg` 与 data/blob URL）、32 步浏览器覆盖（含钱包列表、市场选择器、`/vaults`、`/staking`、`/referrals`、`/api-wallet`、三类市场入口与现货交易对）零条 `img-src` 报告，以及接收器三小时内除探针外零条 `img-src` 报告；登录后的界面未覆盖，靠强制策略附带的 `report-uri` 继续观察。`style-src` 的 `'unsafe-inline'` 保留：Base UI、react-grid-layout 与 TradingView 依赖内联样式。
5. **内联脚本哈希随发布轮换，策略保留上一版集合。** 预渲染页的三段内联脚本里，TanStack 流屏障含资源文件名与预渲染时间戳，每次构建哈希都变，所以哈希不进仓库：`scripts/collect-inline-script-hashes.mjs` 在构建末尾从最终 HTML 算出集合（按 HTML 解析器看到的文本：CR/CRLF 归一为 LF、脚本里的 U+0000 换成 U+FFFD——流屏障序列化的路由匹配 id 含 NUL，首次发布按文件字节算的 7 个流屏障哈希浏览器全部不认，靠浏览器覆盖发现）并拒绝内联事件处理器与 `javascript:` URL；`apps/terminal/tests/browser/csp-coverage.mjs` 在页面脚本之前注册 `securitypolicyviolation` 监听遍历双端页面与弹窗，是独立于收集器的信号，每次发布哈希策略后必须跑；`deploy.mjs functions` 发布时把本次构建的集合写为 CURRENT、线上函数的 CURRENT 写为 PREVIOUS（失效完成前边缘最多还服务上一版页面 60 s；同一构建重发保留 PREVIOUS；2026-09-15 起 `functions --origin <线上源>` 还会抓取线上各预渲染页当前内联脚本的哈希并入 PREVIOUS——上一次函数发布后若上传失败或取消，线上页面仍是更早的版本，只按上次函数发布轮换会删掉它们的哈希而白屏；不带 `--origin` 时打印警告并退回只看上次发布的规则），`sync` 上传前核对线上策略已含本次构建的哈希，`verify` 抓取线上 7 页逐一核对。viewer-response 函数改为一份目录模板加 `frame-ancestors`、`img-src`、`script-src` 三个槽位在边缘拼出三份策略，含两版哈希时约 6 KB（原先三份完整策略 7.7 KB，加哈希会逼近 10 KB 上限）。`cspScriptHashes` 选 `report-only`（强制策略不变，只有 report-only 头带哈希与 `'report-sample'`）或 `enforce`（现状：强制策略也用哈希并附 `report-uri`，图表 iframe 策略不变）；改回 `report-only` 即秒级撤回。被拦截的流屏障会让 TanStack 的水合入口抛错、应用不启动，所以策略与页面不匹配是白屏而不是降级，这也是 `sync` 守卫与 PREVIOUS 集合存在的原因。否决的备选：外置流屏障脚本（零轮换，但冷加载多约 1 RTT）、`'unsafe-inline'` 与哈希并存（现代浏览器等价于纯哈希，审计上模糊）、`'strict-dynamic'`（应用脚本全部同源，不需要）。
6. **每条收紧目录单独切换，候选与强制相同时不再重复下发。** `edge-config.json` 的 `cspImageSources` 与 `cspScriptHashes` 各自取 `report-only` 或 `enforce`；函数在边缘按两个开关拼出强制策略，只有强制了任一收紧目录时才附 `report-uri`。当候选策略与强制策略逐字相同（两项都 `enforce`）时省略 report-only 头，否则浏览器会把每条违规报两次（`disposition` 分别为 `enforce` 与 `report`）。下一轮收紧（例如 `style-src`）时把新目录先加进候选策略，report-only 头会自动恢复。

## 备选方案与取舍

- 把报告发到签名源 `/api/csp-report`：浏览器不会附带载荷哈希，OAC 直接拒绝，否决。
- Lambda@Edge 收报告：需要 us-east-1 的另一套部署与更高成本，否决。
- 直接收紧不观察：`img-src` 的第三方来源无法从代码穷举，误伤钱包图标与头像，否决。

## 后果与边界

- 报告只反映真实用户会话，本机与 Playwright 验证不会触发第三方图片；需要等真实流量。report-only 策略会报告它自己会拦截的一切，包括现行策略早已拦截的项（首条真实报告就是 `vendor-tanstack-router` 块里的 `eval`，现行 `script-src` 同样没有 `'unsafe-eval'`），评估第二步时要按候选策略与现行策略的差集看。该 `eval` 的来源是 Zod 4 的 `util.allowsEval`：第一个 `z.object()` 构建时用 `new Function("")` 探测能否 JIT，探测被策略拦下并上报，Zod 随即退回普通解析器，页面无异常。2026-09-14 起终端与 `hl-react` 的每个 schema 模块都经 `apps/terminal/src/lib/zod.ts`、`packages/hl-react/src/zod.ts` 导入 Zod，包装模块先执行 `config({ jitless: true })` 再 `export * from "zod"`，依赖顺序保证配置先于任何 schema 构建；`zod-jitless.test.ts` 钉住配置、探测未发生与"不得直接导入 zod 值"。第一次尝试把配置放在水合入口的第一条导入里无效（发布 p9 仍每页一条 `eval`）：打包后一个 chunk 的静态导入先于它自己的代码执行，其它 chunk 里的 schema 先构建了。服务端渲染与 Lambda 不受影响，性能不变，因为在策略下 JIT 本来就不可用。
- 接收器是公开端点，任何人都能写日志；预留并发、正文上限与每分钟限额把成本封顶。
- 过渡期 Nitro（EC2）不发 report-only 头，只有 CloudFront 目标参与观察。
- 2026-09-14 实测：接收器函数经 IAM 直接调用返回 204，但 `AuthType=NONE` 的函数 URL 对任何请求都回 403 `AccessDeniedException`，资源策略（`Principal: *`、`FunctionUrlAuthType: NONE`）正确，重建 URL 无效，与账号级"Lambda 函数 URL 公开访问阻断"一致；本机 `aws-cli 2.36.2` 没有 `get/put-public-access-block-config`，`put-function-concurrency 2` 也因账号并发下限被拒。启用步骤：升级 AWS CLI 后对函数或账号执行 `put-public-access-block-config --public-access-block-config BlockPublicPolicy=false,RestrictPublicResource=false`（或在控制台关闭），确认 `curl -X POST` 返回 204，再把函数 URL 写进 `edge-config.json`、渲染并 `deploy.mjs functions --execute`。
- 2026-09-14 更正（同日晚些时候）：上一条的判断不成立。AWS CLI 升到 2.36.44 后确认 Lambda 服务模型没有公开访问阻断操作；用 root 新建的探针函数复现了同样的 403，补上文档要求的第二条资源策略语句（`lambda:InvokeFunction`，条件 `lambda:InvokedViaFunctionUrl: true`，CLI `add-permission --invoked-via-function-url`）后立刻返回 204。AWS 自 2025 年 10 月起要求函数 URL（含 `AuthType=NONE`）同时具备 `lambda:InvokeFunctionUrl` 与 `lambda:InvokeFunction`，只授前者时任何经 URL 的请求都是 403 而直接 `invoke` 正常——与 [ADR 0005](0005-spa-static-shell.md) 决策 13 里 CloudFront OAC 源的"双权限"是同一规则。接收器补齐语句后 `GET` 返回 405、样本 `POST` 返回 204 并在 CloudWatch 出现 `csp_violation` 事件；随后 `cspReportUri` 填入接收器 URL、重新渲染并发布函数，探针函数已删除。
