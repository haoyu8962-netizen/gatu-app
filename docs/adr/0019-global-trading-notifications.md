# ADR 0019：交易任务和普通提示共用全局 Sonner 宿主

- 状态：已接受并实施，2026-09-21；尚未发布。本记录描述本次采用的决策，不把历史审查或自动化检查当作真实交易验收。
- 归属 Reference：[全局操作通知规范](../trading-notifications.md)。关联：[确认面契约](../confirmation-surfaces.md)、[资金反馈方案](../funds-dialog-outcome-plan.md)、[ADR 0014](0014-market-close-submit-and-dismiss.md)。

## 背景与目标

既有 Sonner 与 `OrderToast` 分别定位在右下角，处理相邻的交易操作却各自维护堆叠和生命周期。[组件审查](../trading-feedback-review.md)复现了两者遮挡、离开交易页后成功未展示即过期、旧账户迟到回包显示给新账户，以及未确认错误在成功后残留。全部平仓虽然有内部跟踪和资产锁，却没有立即可见的任务，部分结果的汇总还把完全成交数称为已接受数。

目标是统一展示与状态归属，让一次请求有连续反馈，同时保留原交易事实、资金核验和确认边界。不是照抄官方通知时长：官方本次核对的全部平仓路径跳过 loading，项目仍选择保留即时反馈和未知状态提醒。外部观察的版本、范围与限制见[官方反馈记录](../work-memory/sessions/2026-09-21-official-trade-feedback-observation.md)。

## 约束

- 不改变签名身份、发单数量、确认上限、资产锁、资金动作标记或重复提交守卫。关闭通知不得解除它们。
- 交易确认仍用静态动词、点击即退场，原提交所有者保持存活。资金弹窗保持既有请求期间生命周期；密钥保存与资金核验不能变成会消失的消息。
- 迟到请求仍可核销原账户事实；只允许当前账户/环境显示相关任务。请求成功不等于成交，更不等于仓位归零。
- 保留已存 pending 数据兼容性。展示字段可选，不能因旧记录缺少市场名或展示 metadata 损坏而丢掉合法的跟踪事实。

## 决策

1. **一个 Sonner 容器。** 根运行时 `AppToaster` 组合 Toaster、订单通知 gate、CCTP 通知与资金恢复桥。gate 在当前身份有可展示任务时才加载 OrderNotificationHost；等待模块加载期间保留队列的最新结果，加载并发布后才计成功时长，避免无任务启动时加载所有交易通知格式器。`OrderToast` 只渲染任务内容，移除独立 portal、定位与移除计时器。普通提示、任务卡、资金恢复使用同一默认三条堆叠。
2. **反馈与执行分离。** OrderQueue 是内存展示层，任务必填 owner/env，使用稳定逻辑 ID 原位更新。普通订单与 TWAP 对账只写 scoped 任务，不再按 queue 存在与否另发无身份 Sonner。撤改单复用原 pending action 与新鲜快照结论；不能从记录消失猜测成功。
3. **状态转换明确清理。** 写入新状态时清除不再成立的错误、结果、计数和仓位标记。保存可翻译语义，渲染订阅 locale，原始交易所错误保持原文。
   - 2026-09-28 修订：「原始交易所错误保持原文」由 [ADR 0024](0024-translate-action-errors-at-render.md) 修订为已知交易所文案翻译、未知的逐字保留，且非交易所错误不再原样显示。
4. **生命周期由呈现控制。** OrderQueue 成功默认只有在 Sonner 最前台才计时 5 秒，后台或尚未到前台不按完成时间过期；其他状态常驻。pending/confirming/unconfirmed 可软隐藏，状态推进重显，关闭不改执行事实。普通短提示保持默认 3 秒，各资金调用方原有 10 秒/未知常驻约定保留。
5. **恢复已有事实，不新建交易日志。** 从仍保存的 pending order/TWAP 恢复任务。新订单存可选反馈 metadata 及已知 HTTP 子项结果；schema 无效时忽略展示字段而保留跟踪事实。旧记录使用通用 Order，不补造交易量。已完成且没有 pending 的通知不在刷新后重放。
6. **一个批次，一张卡片。** 全部平仓关联逐市场请求量、可证实的成交量与结果，部分和未知持续可查。只有状态 `filled` 而无数量证据的子项标为 `filled-unverified`，不冒称 Fully filled。后台对账不能设置全部仓位已平；该结论仍需原提交路径的新仓位快照。
7. **资金保留专用状态机。** CCTP 保持自己的持久跟踪记录及同 ID 标准通知；资金恢复提醒迁入 Sonner custom，Review、核验、marker 和两步清理不变。API 钱包一次性密钥、金库/质押结果未知面板继续保留。
8. **位置遵循应用断点。** Toaster 的普通与 mobile offset 都使用项目 `<=1000px` 规则，避开底部导航和安全区；所有内容使用共享 overlay 与 z-toast 令牌，不用调高 z-index 掩盖两套布局的冲突。

## 备选方案与代价

| 方案 | 取舍 |
| --- | --- |
| 保留两个容器，错开位置或调 z-index | 无法一起解决跨路由存活、成功计时和多条高度变化；移动端还需要维护第二套布局。未采用 |
| 换成官方使用的通知库 | 问题来自本地边界，现有 Sonner 支持 custom、ID 更新、关闭回调与无限时长，无需换库。未采用 |
| 为每个平仓子单各发一个 toast | 多市场部分结果易刷屏，也丢失批次关联；改为单卡可滚动明细 |
| 所有请求使用 `toast.promise` | Promise 只描述网络返回，不能描述成交、最终对账与资金核验；保留业务状态机 |
| 所有通知永久持久化为历史中心 | 会引入第二份交易真值、清理和隐私成本；本次只恢复已有 pending 事实，不承诺完整历史 |
| 所有资金弹窗也点击即关闭 | 与现有尝试身份和核验流程冲突；不属于本次展示统一，保留专用面板 |

代价是需要 owner/env 过滤、任务与 Sonner ID 的桥接、子项 metadata 和前台计时协调。第一次有可展示订单任务时需要加载通知模块；队列负责保留这段时间内的最新结果。常驻失败/未知消息会占用堆叠，用户需要关闭或完成核验；不提供自动重试来减少这一步。并发数量由 Sonner 展示规则决定，不能据此推断交易执行顺序。

## 2026-09-22 时长决定修订

用户要求未确认、部分成交等结果使用三秒短提示，因此决策 4 中「其他状态常驻」、决策 6 中「部分和未知持续可查」及上述对应代价被局部替代：unconfirmed、partial、failed、canceled 只在 Sonner 最前台计时三秒；pending/confirming 继续常驻，成功及专用资金通知时长不变。自动关闭沿用手动 dismiss 语义，未确认软隐藏并保留任务与执行事实，新状态仍可重显；不采用直接删除未确认记录的方案，以免未变化的对账再次弹出通知。完整历史中心仍未引入，用户需到订单与成交记录核对详情。本次是用户指定的产品时长，不宣称官方所有状态都使用三秒。实际验证见[三秒结果通知任务](../work-memory/sessions/2026-09-22-notification-result-timeout.md)。

## 验证与交付边界

2026-09-22 生命周期补充：保留一个 Sonner 容器及展示 ID 与任务 ID 分离，发布改为可取消 microtask；每个展示实例独立失效，内容订阅当前任务与展示有效性，并在失效后补发本实例关闭，覆盖 Sonner 异步插入晚于首次关闭的竞态。获准关闭先同步结束展示，再修改 queue，避免同批结果沿用正在退出的 ID。代价是增加一个仅管理展示存活的外部订阅对象；它不存交易事实、不计时、不重发交易。仅延后发布无法覆盖真实卸载，仅隐藏内容留下空白容器；不采用关闭 StrictMode、永久复用 ID 或无证据升级依赖。回归与实际结果见[生命周期修复任务](../work-memory/sessions/2026-09-22-notification-lifecycle-fix.md)。

- 实际执行的命令、失败修正、最终版本和浏览器观察由[本次交付任务记录](../work-memory/sessions/2026-09-21-global-sonner-notifications.md)保存，本文列出的要求不冒充已执行结果。mock / 隔离浏览器验证不能证明主网资金、外部钱包和真实触屏行为；未在本次迁移中执行新的真实交易或发布。
