# ADR 0040：邮箱钱包主网到账后自动存款

- 状态：已接受并实施（用户明确要求，2026-10-10）；2026-10-11 经 PR #97 合入 `dev`（`ee4aab99`）、随 PR #96 晋升 `main`（`ff11eee5`）并随 [p30](../work-memory/sessions/2026-10-11-cloudfront-release-p30.md) 发布，主网赞助充值开关开；真实主网自动存款与最终 HyperCore 入账验收未做。
- 关联：[CCTP 充值](../cctp-deposits.md)、[初次排查](../work-memory/sessions/2026-10-10-mainnet-deposit-manual-trigger-investigation.md)。

## 目标与约束

用户明确要求移除主网自动执行限制，恢复向邮箱充值地址转账后自动转入交易账户的流程。此决定取代 `0c72fa857` 引入的主网强制二次点击要求；不改变外部钱包的手动存款或任何已广播请求的恢复规则。

## 决策

- 主网、测试网共用页面级 `EmbeddedDepositAutoBridge`，分别服从其已有赞助充值开关。精确邮箱 owner 的有效 USDC 余额达到 CCTP 最低金额后，自动签名并通过赞助钱包提交。已有余额也可在会话恢复后被处理，无需重新打开弹窗。
- 邮箱表单保留地址、网络、费用、必要限制与 Done，移除手动余额按钮及要求返回点击的说明，说明自动转入行为。外部钱包仍复核用户输入的金额和费用后手动提交。
- 移除执行入口对主网 `automatic` 的一律拒绝。自动路径沿用当前余额、实时费率和金额上限；手动调用仍受已有复核值约束。自动调用把提交的整笔余额当作锁定值：执行边界在资金锁内签名前、广播前各重读一次原生 USDC 余额，与提交金额不等即中止，由宿主用刷新后的余额重试；自动调用没有弹窗门控，所以签名前先核验精确 owner 的最新法律状态，广播前再核验一次；宿主对无哈希提交或未能确认的已提交交易显示常驻「Deposit status unknown」警告，不报失败（2026-10-11 审查补充，含 PR #97 Codex 机器人的两条 P1）。2026-10-12 Codex CLI 复审补充：宿主只有在法律状态已知且允许操作（已接受条款）时才具备资格，此前不读余额、不尝试、不提示，接受后自动开始；执行边界的法律核验绑定将要签名的账户（`owner: ready.address`），与当前选中 owner 不一致即在请求和签名之前失败；存在未解决的赞助授权意向时不发起新的自动尝试，常驻的未知状态警告不会被覆盖。2026-10-13 生产审计补充：授权尚未交给 bundler 的失败（无哈希、无未解决授权意向、结果不是未知；签名后、保存意向前的费用复核失败也属此类，该授权没有发出，下一次会用新的 nonce 覆盖）按宿主的退避重试，此前会停在失败状态直到余额变化，而邮箱表单已没有手动存款按钮；可能已到达 bundler 的提交仍不自动重发。
- 精确 owner、最新 CCTP 路由、地区、法律状态、最低金额/上限、Fast Transfer 容量、Smart Wallet 链及 paymaster、资金锁、授权 nonce、严格回执、未知提交意图和恢复记录全部保留。自动流程不能在错误/未知结果后盲目重新授权。
- 自动执行由运行中的应用页面承担，关闭存款弹窗不停止页面级处理；关闭所有页面后不承诺继续发起存款，已提交交易仍按协议处理。此次不建设服务端托管签名或充值地址服务。

## 替代方案与取舍

- 仅隐藏按钮会使资金停在钱包；仅放开页面级开关仍会被执行入口拒绝，因此同时调整两个边界及表单。
- 保留每笔第二次点击与用户明确要求冲突，不采用。也不把测试网行为的存在当作主网实盘验收证据。
- 自动处理的是精确邮箱钱包的可用 USDC，包含会话恢复时已存在的余额；界面明确说明自动转入。外部钱包和 Agent-only 会话不进入该自动路径。

## 验证标准

- 主网真实自动组件联动真实 `useDeposit`，以模拟的钱包、RPC、Circle 和回执验证无需点击即可调用主网赞助合约，并记录恢复信息；对应旧代码必须失败。
- 覆盖主网与测试网、关闭开关、非邮箱身份、余额不足、路由错误、重复渲染/并发、既有恢复与不确定结果；资金守卫回归继续通过。
- 邮箱表单不再提供第二次 Deposit；外部钱包表单保留原行为。检查多语言、类型、相关测试及生产构建。
- 自动化验证不等于已发布或真实资金到账；真实钱包与最终 HyperCore 入账验收单独报告。

## 实施与验证结果

主网自动 scope 与真实宿主联动的旧实现回归先失败、修改后通过。最终相关 324 项、Chrome 六组表单回归、类型检查和开启主网赞助开关的生产构建通过；全量首次运行的两项样式计数失败已按实际删除量下调并复测。完整命令、版本、失败与未验证范围见[任务记录](../work-memory/sessions/2026-10-10-automatic-email-deposits.md)。未进行真实资金存款、推送或发布。
