# 订单簿高度与边缘布局规范

## 目标

桌面订单簿、移动端紧凑订单簿和移动端左右分栏订单簿，均按实际容器高度铺排档位，避免将不足一行的剩余高度积累为顶部或底部空白。本规范先于实现更新。

## 几何规则

- 桌面与移动端普通分栏：行高 23px，行间距 2px；移动端紧凑模式：行高 24px，行间距 4px。
- 档位容器不设垂直内边距，不使用 `justify-between`、拉伸行高或分散间距填满空间。
- 需要渲染的行数向上取整：`ceil((可用高度 + 行间距) / (行高 + 行间距))`。完整可见行数向下取整；两者分别用于展示与操作权限。
- 桌面先扣除实际价差栏高度，再平分两侧高度。紧凑双边模式先扣除中间价行与两段间距，再平分；单边模式使用完整高度，不保留中间价行或强制奇数行数。
- 卖盘从中间价向上排列，买盘从中间价向下排列。移动端普通左右分栏的两侧均从顶部向下排列。每侧独立裁剪远端溢出，不能遮挡最优报价或中间价栏。
- 容器尺寸保留小数精度；尺寸变化时同步更新展示和交互边界，不能仅在向下取整的行数变化时刷新。
- 移除与可视高度无关的 20/24 档、19 槽布局上限。行情订阅仍遵循原有深度限制；有多少真实档位就展示多少，其余使用无价格、不可交互的占位，不能生成虚假行情。
- 正常行、骨架、占位共用相同覆盖行数和固定几何。保留价格键与紧凑模式按档位排名定位的方式，避免更新行情时重建未变化的行。

## 操作边界

- 被裁剪、完全在视区外或尚未测量确认完整可见的档位，不得通过鼠标、触屏或键盘选入价格；禁止对这些行启用长按操作。
- 完整可见并不等于行情可用，仍需通过市场身份、订阅状态、新鲜度和缓存检查。布局调整不能解除任何已有数据保护。
- 行间距本身，以及真实深度不足时的占位，不属于异常留白。不得为填充空间拉长深度柱或伪造价格。

## 验证

1. 覆盖整数与半像素高度、整行边界前后、超出原有行数上限的高容器。
2. 在桌面、窄桌面、普通移动端和紧凑移动端检查边缘覆盖、固定行高、间距及最优报价锚点。
3. 缩小后被裁剪的行立即禁用；扩大后完整显示的行恢复原有交互资格；切换双边、仅卖盘、仅买盘后重新核对几何。
4. 加载、稀疏快照、空快照与错误恢复使用一致布局，页脚和中间价不因行情条数改变位置。
5. 保留行情更新的 DOM 身份、焦点与 CLS 回归检查；运行相关 Vitest、浏览器尺寸验证、Biome 与 TypeScript 检查。
