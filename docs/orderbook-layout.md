# 订单簿高度与边缘布局规范

## 目标

桌面订单簿、移动端紧凑订单簿和移动端左右分栏订单簿，均按实际容器高度铺排档位，避免将不足一行的剩余高度积累为顶部或底部空白。本规范先于实现更新。价格、数量和累计量必须完整可读；不得以填满边缘为由裁切真实数据。

桌面列头、侧容器与价差 chrome 由真实组件的纯视图 `OrderbookPanelView` 提供；启动阶段不渲染盘口占位树，见 [ADR 0010](adr/0010-blank-until-ready-startup.md)。

## 几何规则

- 桌面与移动端普通分栏：最小行高 23px，行间距 2px；移动端紧凑模式：最小行高 24px，行间距 4px。字体、字号与行间距保持固定，行内容垂直居中。
- 档位容器不设垂直内边距，不使用 `justify-between`、缩放文字或分散间距填满空间。
- 完整行数 `n = floor((可用高度 + 行间距) / (最小行高 + 行间距))`。当 `n > 0` 时，实际行高为 `(可用高度 - (n - 1) * 行间距) / n`，所有档位统一使用它；不足一完整行时保持空容器。不得额外渲染半截报价。
- 桌面先扣除实际价差栏高度，再平分两侧高度。紧凑双边模式先扣除中间价行与两段间距，再平分；单边模式使用完整高度，不保留中间价行或强制奇数行数。
- 卖盘从中间价向上排列，买盘从中间价向下排列。移动端普通左右分栏的两侧均从顶部向下排列。每侧恰好容纳全部完整档位，不能遮挡任意报价或中间价栏。`overflow-hidden` 仅作为容器边界保护，不能用于有意裁切价格。
- 容器尺寸保留小数精度；尺寸变化时同步更新展示和交互边界，不能仅在完整行数变化时刷新。行情条数、价格和数量更新不改变行数、行高或档位排名间距。
- 移除与可视高度无关的 20/24 档、19 槽布局上限。行情订阅仍遵循原有深度限制；有多少真实档位就展示多少，其余使用无价格、不可交互的占位，不能生成虚假行情。
- 正常行、骨架、占位共用相同完整行数、实际行高与排名间距。保留价格键与紧凑模式按档位排名定位的方式，避免更新行情时重建未变化的行。
- 深度条宽度为该档累计量除以该侧当前可见档位的最大累计量，上限 100%。买卖两侧各自取自己的最大值，因此两侧长度独立变化，不共用同一基准。
- 深度条是同色实色填充、透明度 0.15，不使用渐变。桌面与紧凑模式左对齐；移动端左右分栏保留既有镜像方向。深度条与视图模式图标共用 `--orderbook-depth-bid/ask`，色值见[新增档位及数量反馈](orderbook-new-level-animation.md)。
- 紧凑订单簿表头按订单簿容器宽度（容器查询）决定资产单位标签是否显示，不读取页面视口宽度。

移动端紧凑双边盘口的 24px 中间栏使用透明背景、不绘制上下边框，与盘口底色连续，仅显示带美元符号的盘口中间价，并提供随语言切换的“中间价”可访问名称；不并排展示价差数值、百分比或价差悬浮标题。单边模式不显示此栏。桌面与普通左右分栏保留各自的价差展示。中间价复用共享行情层提供的 `activeAssetCtx.ctx.midPx`（现货为 `activeSpotAssetCtx.ctx.midPx`），仅展示当前市场有效且新鲜的值；缺失、null 或失效时显示占位，不回退到 BBO 均价、盘口均价或标记价。紧凑盘口不为该显示订阅 BBO，普通左右分栏的价差计算保留原订阅。切换市场或数据恢复的首个价格建立方向比较基准；方向颜色、占位及档位几何规则保持不变。

## 操作边界

- 桌面刷新、首份快照等待、失效与重连期间保留表头、价差占位及两侧完整档位的空占位，不显示可见的“等待订单簿”或被动加载失败文字。等待状态可以使用 `aria-busy` 与屏幕阅读器专用说明；仅当前成功快照可展示真实报价或“暂无订单”。空占位不能选价，恢复后继续使用原有档位几何。
- 所有渲染出的真实档位均须完整可见。尚未测量确认布局时不展示真实价格，不得通过鼠标、触屏、键盘或长按选入价格。
- 完整可见并不等于行情可用，仍需通过市场身份、订阅状态、新鲜度和缓存检查。布局调整不能解除任何已有数据保护。
- 行间距本身，以及真实深度不足时的占位，不属于异常留白。不得为填充空间改变深度柱的横向占比或伪造价格。
- 每个订单簿共用一个累计深度提示；紧凑与左右分栏均显示距中间价、平均价格、累计基础资产和累计计价资产。鼠标悬停跟随可见档位排名，键盘焦点与触屏长按跟随价格；行情更新保持价格键和现有反馈。
- 移动端长按 450ms 显示提示并抑制随后一次选价点击，移动超过 8px 取消长按，普通点击仍填入价格。提示不拦截滚动、不改变行高或订阅；失效行情、身份或视图几何变化关闭提示。紧凑两侧在远离中间价的边缘绘制累计边界，左右分栏两侧均在底部绘制。

## 验证

1. 覆盖整数与半像素高度、整行边界前后、超出原有行数上限的高容器。
2. 在桌面、窄桌面、普通移动端和紧凑移动端检查边缘覆盖、完整文字、统一实际行高、固定间距及最优报价锚点。
3. 缩小后减少完整行数，扩大后增加完整行数，所有真实价格、数量与累计量的文字边界都包含在视区内；切换双边、仅卖盘、仅买盘后重新核对几何。
4. 加载、稀疏快照、空快照与错误恢复使用一致布局，页脚和中间价不因行情条数改变位置。
5. 保留行情更新的 DOM 身份、焦点与 CLS 回归检查；运行相关 Vitest、浏览器尺寸验证、Biome 与 TypeScript 检查。

## 参考实践

颜色、悬停、移动端视图和缩放命中区的最新实测对照见[订单簿参考实践与修复计划](orderbook-ui-reference-audit.md)。该文档区分已观察事实与待实施方案，不替代本规范的现行几何规则。

新增档位的整行背景动效遵循[订单簿新增档位动效实施方案](orderbook-new-level-animation.md)：基于完整有效实时快照差分，首帧、缓存与重连恢复保持静默。各端共用一次性 800ms 覆盖层；它位于深度条之上、文字之下，不接收指针、不改变本文的行几何规则。价格与图形使用独立主题 token，数字文字须通过完整动画叠层的对比度验收。

在 [Hyperliquid HYPE 终端](https://app.hyperliquid.xyz/trade/HYPE) 的 1545×1391 桌面视口实测：订单簿使用完整的 23px 行与 2px 间距，居中排布后顶部、底部各保留约 4px 余量，没有裁切价格。该观察仅代表此次视口与状态，不断言其所有模式相同。本项目采用完整报价原则，并按消除明显边缘留白的需求将余量分配到行容器内；自适应行高是本项目的实现选择。
