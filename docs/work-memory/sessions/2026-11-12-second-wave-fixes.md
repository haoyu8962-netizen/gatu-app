## 结论与依据

### 做法依据

- **P2-10 设置跨标签页**：2026-11-12 在官方终端 `app.hyperliquid.xyz` 上取证：每项设置各用一个 localStorage 键（`hyperliquid.…`），已加载的 60 个脚本里没有 `storage` 事件监听。所以官方的旧标签页不实时跟随，但也覆盖不了别的设置。本终端是单条目存储，必须自己做到「只写本页改过的字段」。
- **P2-13 签名地址核对**：官方文档 Signing 页写明，签名不对时交易所恢复出另一个地址，并按那个地址报错或执行。所以 owner 签名返回后在本地恢复地址并比对。
- **nonce**：官方文档 Nonces and API wallets 页：每个签名者保留最高的 100 个 nonce，新 nonce 必须大于其中最小的、未用过，并落在 (T − 2 天, T + 1 天)。
- **P1-3**：CloudFront 文档写明 5xx 默认按 error caching minimum TTL 缓存 10 秒，但托管策略 CachingDisabled 下不缓存；仓库的分发配置给 `/api/*` 用的正是它。线上实配没有核对。

### 修改

| 项 | 修改 |
| --- | --- |
| P2-10 | 全局设置写入只合并本页改过的字段；监听 `storage`（以及从往返缓存恢复时）走原有校验路径同步；两个当前页签字段只在本窗口生效；损坏或更高版本的数据被忽略 |
| P2-13 | owner 签名返回后用同一份 typed data 恢复签名地址并与所选 owner 比较，不符或无法恢复就不发送，按钱包账户不符报告。覆盖外部钱包、嵌入式 owner、两种 Agent 授权与两种条款签名；本地 Agent 私钥不检查 |
| P1-3 | 判定按单个地址缓存；每个网络（IPv4 /24、IPv6 /48）每实例 20 次、每实例合计 120 次的外呼额度，耗尽回 503 `budget_exhausted`（客户端按不可用处理）；失败写一行不含完整地址的 JSON 日志 |
| P2-15 | 语言目录等待加 3 秒上限，超时以英文揭示，目录到达后热切换 |
| P2-16 | 壳里新增入口看门狗内联脚本：入口脚本 `error`、`load` 之后 5 秒、或 60 秒内入口没有报到时显示重新加载界面；`client.ts` 第一句报到 |
| P2-14 | 手机扫码导入页在导入前后显示账户地址；手机已有会话时提示导入会替换它。新增一条文案，七个语言目录都有译文 |
| P3 实时 | 页脚连接状态来自 store 的 `transportStatus`；`bbo` 在断线或离线时标过期；`refreshKey` 换键时沿用同一基础键的最后一帧与接收时间（只限完整状态频道） |

### 对抗审查与裁定

Codex 报「已到用量上限，11 月 17 日恢复」，没有跑成。改由一个独立的 Claude 审查代理（Opus 5.5，只读，带内存实验）按同一份提示词审查：6.5 分，1 项 P1、2 项 P2、4 项 P3；签名地址核对与扫码导入页没有发现问题。

- **P1（主会话自己接线引入）**：nonce 的未来窗口改按交易所时间估算之后，设备睡眠超过一天时估算偏低（单调时钟在睡眠时停走），提款、划转、授权会在本地被一直拒绝。修法：两只时钟不一致时 `estimateNow` 返回 `undefined`，退回原来按设备时钟判断的行为。
- **P2**：实现代理把判定也按 /64 缓存，一个地址会继承同一 /64 里邻居的代理标记（共享 /64 的托管商、Teredo）。裁定：判定改回按单个地址缓存，/64 只用于推荐接口的限流键。
- **P2**：只有每实例总额度时，一个 /48 轮换地址就能耗尽它，让正常新访客被拒。修法：先扣每网络额度，耗尽只拒绝该网络，不动总额度。
- **P3 已修**：从往返缓存恢复的页面补一次设置同步。
- **P3 未修，记为边界**：见下。

## 验证与限制

读数在 `claude/second-wave-fixes` 的工作区上取得（Node 22.15.0）。

- `pnpm typecheck`：退出码 0。
- 终端全量 Vitest（`--maxWorkers=4`）：最后一次全量运行 727 个文件通过、1 个失败、1 个跳过；10,404 项通过、1 项失败。失败的是 `mobile-agent-sync-modal.test.tsx` 的「reveals the QR after a two-second hold…」，单独重跑通过（35 项里全部通过），判断为全量负载下的超时，不是这次改动造成；此前一次全量运行里它是通过的。该次运行之后只改了一个测试文件的类型标注，没有再跑全量。
- `node --test scripts/ci-workflows.test.mjs`：20 项。
- 生产构建（固定身份、配对关闭、没有 `.env.local`）：450 个分块、无循环静态导入。相对第一波：总量 +3,527、交易启动 +2,905，交易启动超出允许值 951；按实测增量上调这两项基线，见[性能基线文档](../../terminal-performance-baseline.md)。上调后在同一份产物上跑完构建链余下步骤，全部通过；壳里的内联脚本哈希从 3 个变为 4 个。
- 各实现代理都报告了「修复前失败、修复后通过」与变异结果（设置 6 个、签名核对 2 组、地区接口 5 个、启动 7 个、实时 7 个、签名存储 4 个、导入页 2 个，均被抓住）。主会话在审查之后的三处修改各补了测试，没有再做变异。

审查指出仍抓不到的变异：删掉 `clients.ts` 里 nonce 管理器的 `readExchangeNow` 接线；设置同步里对 `storageArea` 的判断。

没有验证的：

- 真实钱包（含 WalletConnect、硬件钱包、Privy 嵌入式钱包）上的签名地址核对；非标准签名形态按设计会被拒绝，没有实测。
- 真实浏览器多标签页、真机、iOS 主屏幕应用；看门狗只在 Playwright 的手写夹具页上跑过 Chromium 与 WebKit，不是构建出来的壳。
- 部署后的 Lambda、真实 IPdata 与线上分发的缓存策略。
- 浏览器套件与配对开启的构建。

已知边界：

- 发版过渡期，仍在运行旧版本代码的标签页会整份写回设置，新标签页会实时应用它；旧标签页关闭后不再出现。
- 存储里是更高版本的设置数据时，本页写入会用自己的整份状态覆盖它；版本号提升之前不会出现。
- 带宽极低（约 70 kbps 以下）时入口 60 秒内到不了，看门狗会误报，失败界面可能留在应用上方。
- Agent 记录的向前兼容只从这一版起生效。
- 地区接口的额度是每实例的，分布式的消耗仍要靠 WAF 与告警；额度数值是保守估计，需要按线上流量调整。
- 两个 localStorage 写入不是跨进程原子操作，两个标签页在几毫秒内同时改不同设置理论上仍可能丢一个。
