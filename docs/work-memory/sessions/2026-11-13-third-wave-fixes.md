# 全局缺陷审查第三波修复

## 背景与范围

同步记录，2026-11-13，未取得任务标识。仓库迁移完成后（[迁移记录](2026-11-13-repository-move-and-chart-library.md)），运营方要求：「请继续处理还不正常或没收尾的，跟着之前发现的问题还有哪些没有修复的请你接着修复。」进行中又要求移除每日的官网行情检查工作流：「因为这个脚本导致了 github 账号被封禁……整个任务的实质就是请求一个第三方网站的接口；请你移除掉。」

范围：[全局缺陷审查](2026-11-12-global-defect-review.md)里剩下、能在代码里完成、不需要运营方先做决定的项。分支 `fix/third-wave`，基于 `main` `cde6f75b`。没有做的见「后续与替代关系」。

## 结论与依据

### 修改

| 项 | 修改 |
| --- | --- |
| P1-4 | `Terminal Tests` 改跑全部 Vitest 文件（729 个，两片，每片 `--maxWorkers=4`），删除十四组手选清单（原清单只覆盖 407 个）。此前在 CI 里连交易所主网与测试网的两个测试改为本地应答，仍在 CI 运行 |
| 定时工作流 | 删除 `website-markets-check.yml`，GitHub 上已先行停用；仓库不再有定时工作流，任何工作流都不请求交易所接口（[ADR 0056](../../adr/0056-no-external-requests-from-automation.md)）。单元测试拦截回环以外的连接；Playwright 的 Chromium 只解析回环地址且不走代理 |
| P1-5 | 启动各时刻与连接恢复摘要写进本机 `localStorage` 的环形缓冲（最近 10 次启动，只有时间与计数）；设置 → 关于新增「复制诊断信息」。没有任何自动上报。记录器在揭示之后才懒加载 |
| P2-17 | 已核实的一例（`status-motion-surface-contract` 不数 `Spinner`）与另外四个用变异证明的漏洞已修：进度文案契约改读提取后的英文目录，弹层关闭控件契约逐条登记表达式，启动字体契约扫全部 CSS，邮箱钱包创建契约跨文件追踪 |
| 存储 | 市场偏好只合并本页改过的所选市场与收藏增删；收藏跨标签页同步，所选市场各窗口独立。Agent 注册会话记录在同一 epoch 内保留未知字段，已知字段仍严格校验 |
| 测试缺口 | 第二波审查指出的两个抓不到的变异（nonce 的 `readExchangeNow` 接线、设置同步的 `storageArea` 判断）各补一条会失败的测试 |
| 订单簿 | 增量 `l2` 降级后按 60 秒起、翻倍、上限 10 分钟尝试回主源，尝试期间备用源继续供数；回切后稳定满 10 分钟才复位（ADR 0003 补记）|
| TWAP 终止 | 资产锁被占用时排队，最多等 15 秒；超时、列表卸载、身份变化三种情况作废，不签名不发送（[通知文档](../../trading-notifications.md)、ADR 0053 表格新增一行）|

复查后没有改代码的两条：`visibility.ts` 的 `resume` 处理第一波已修并有测试钉住；排行榜上游超时的审查前提不成立（依据的是部署手册里过时的 10 s，ADR 0006 决策 8 已是 30 s），只补了测试并更正手册。

### 对抗审查与裁定

Codex 的用量上限到 2026-11-17，没有用。由一个独立的 Claude 审查代理（Opus 5.5，只读）审全部未提交改动：7 分，没有 P0、P1，7 项 P2。

- **订单簿主源「首帧后又失败」时每 60 秒来回切换**：已修，加 10 分钟观察期。
- **TWAP 终止排队无上限；排队中卸载被丢弃却报「失败」**：已修。加 15 秒上限；超时用 ADR 0053 现成的「未签名未发送」文案，卸载用现成的「请求未提交」，没有新增可翻译文案。执行宿主仍在页签面板里，没有搬到页面层。
- **Playwright 的闸在系统代理下失效**：已修，加 `--no-proxy-server`。对 IP 字面量的请求仍不拦，写进 ADR 0056。
- **进度文案扫描器可被 Biome 换行绕过；邮箱钱包契约只看本文件**：已修。前者改读目录后有一个时序边界：源码改了、还没重新提取时看不到。
- **ADR 0056 关于 CI 外部访问的说法不属实**：已更正，如实列出两个 Claude 工作流与软件源。
- P3 里已修：单测闸把数字字符串当成管道名放行。其余 P3 记在下面的边界里。

审查方独立核对了会话记录那个没被测试抓住的变异（「从校验不过的记录里也带出未知字段」），同意该路径走不到。

主会话在整合时把诊断的 store 接线从根路由挪到了客户端运行时的 provider 树里；这处改动对包体没有可测的影响。

## 验证与限制

读数在 `fix/third-wave` 的工作区上取得（Node 22.15.0），均为最后一次代码改动之后：

- `pnpm typecheck`：退出码 0。
- 终端全量 Vitest，按 CI 的命令两片各跑一次：第一片 368 个文件通过、1 个跳过，5,520 项通过；第二片 368 个文件、4,994 项通过。没有失败。
- `node --test scripts/*.test.mjs`：80 项通过。
- 生产构建（固定身份、配对关闭、没有 `.env.local`）：无循环静态导入；相对 `main` 总量 +6,793、交易启动 +3,499、`trade-terminal-page` +743，后两项超出允许值，按实测增量上调三项基线，见[性能基线文档](../../terminal-performance-baseline.md)。上调后预算检查、壳预加载注入、内联脚本哈希收集与图表产物校验通过。
- 七组浏览器回归（CI 的同一批命令，不分片）带最终的 `--host-resolver-rules` 与 `--no-proxy-server` 全部通过：22、55、47、36、46、19、2，共 227 项。
- `pnpm memory:check`：通过。删除定时工作流后，1 份旧记录（`2026-11-02-weekly-memory-review`）的证据来源里指向该文件的条目随之移除，正文未改。
- 各实现代理都报告了「修复前失败、修复后通过」与变异结果；逐项数字在各自的报告里，没有抄进本记录。

没有验证的：

- 新仓库上的 CI：全量两片在运行器上的耗时与 20 分钟超时是否够用。
- 真实浏览器与真机：多标签页收藏同步、TWAP 排队时的 Web Locks 中止、订单簿回切时不闪烁、诊断记录在 iOS 上的写入时机，都只有 jsdom 下的测试或读代码的结论。
- 真实钱包、部署后的行为。
- 配对开启的构建。

已知边界：

- 封停原因没有经过 GitHub 确认；「定时工作流是原因」是运营方的判断。
- 两道网络闸不是完整的沙箱（见 ADR 0056「后果与边界」）。
- 没有任何东西会再提醒官网快照过期；构建里的 7 天规则还在，大约 2026-11-20 之后触发官网构建的 PR 会失败，直到有人在本机刷新快照。
- `mobile-data-presentation-contract` 只拦退役文案的黑名单，新写的被动警告文案拦不住；证明了但没修。
- 契约扫描器仍有绕过方式（不经 Lingui 的省略号字符串、经 context 或全局 store 传出的创建函数等），列在契约代理的报告里。
- 诊断记录里有每次启动的绝对时间戳，复制时一并带出；字体等待超时也记成 `fonts` 时刻，没有超时标记；启动时连 JS 块都取不到的那次启动不会有记录。
- 会话记录保留的未知字段可能脱离它依赖的已知字段（本版本清掉注册元数据时仍保留），失败方向是判成无效会话。

## 后续与替代关系

本记录不取代其他记录。

需要运营方决定或操作的：

- 是否把官网快照的日期规则从构建挪到发布前的检查，或者改为每周在本机刷新。
- 线上 Lambda 的超时是否确实是 30 s（代码与文档都按 30 s）。
- `mobile-positions-view.tsx` 账户页签计数里的被动加载转圈是否合规；`command-menu.tsx` 没有关闭控件是否接受。
- `wallet-modal.tsx` 的 `PrivyWalletLauncher` 在对话框打开时于 effect 里重连、可走到邮箱钱包创建，是否符合 ADR 0033（目前按「对话框只由点击打开」登记）。
- TWAP 超时文案里的「checks」不贴切，是否值得新增一条文案与七种语言的译文。

没有处理的：P2-18 文档状态漂移、P2-19 巨型组件重构、发布从不删除旧文件、IAM 文件里的账号标识、死代码与依赖、规则体量、iOS 启动图；把 TWAP 终止的执行宿主搬到页面层；给契约登记加「导出组件且含转圈位点的文件自动算包装组件」。
