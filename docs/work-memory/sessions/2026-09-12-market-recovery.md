# 行情恢复：字段来源、静默占位与操作守卫

## 背景与范围

用户从后台返回浏览器时短暂看到“标记价格不可用”，也发现移动与桌面报价来源及账户加载表现不一致。后续相关任务“修复订单簿加载状态”（`01a09420-9a4a-7610-b1f0-dca26466175a`）扩展检查被动数据提示与空态。

## 结论与依据

- 被动初始加载、过期及重连不展示错误/等待文字、警告图标或按钮错误标签；使用稳定数值占位、空列表或骨架。保留无障碍忙碌状态。
- 隐藏提示不能移除新鲜度、身份、账户、签名或操作可用性守卫。动作禁用由独立布尔状态决定，不能由有没有错误文案决定。
- 只有完整、当前、成功的快照才能确认空账户/空列表。订阅已激活不等于已经收到首帧；未知或失败不得触发存款建议。
- 用户主动请求的操作结果仍须反馈，尤其是不确定的交易结果。
- 标题价格使用同一资产 ctx 的 `midPx`，允许其为空时按已定义规则回退 `markPx`；24 小时差额与 `prevDayPx` 保持同一上下文。紧凑盘口中间价只取服务端 `ctx.midPx`，不以标记价填充。
- 标记价、预言机价和 BBO 价差各自有合法用途；不要把所有字段统一替换成一个“价格”或用显示回退解锁交易。

## 验证与限制

证据来自上述提交及三个专题文档；本次未重演十分钟后台挂起。已有账户/盘口回归记录属于对应提交，不能据一次数百毫秒页面恢复宣称普遍性能指标。需覆盖首帧缺失、过期/错误恢复、真实空快照及禁用操作。

## 后续与替代关系

新被动提示类别必须先更新展示规范。旧红字提示与把失败视为空账户的实现不得恢复；SDK 字段语义需核对固定版本和具体接口，不能仅凭 Hyperliquid 页面外观推断服务端字段。
