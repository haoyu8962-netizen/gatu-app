# 官方已登录只减仓表单实测与修复规划

## 背景与范围

同步记录。用户表示已在官方终端登录有仓位账户，要求继续调试并规划修复。基线 7342b7f3，初始工作区干净。未取得任务标识；页面上的邮箱、精确仓位量、资产金额和截图未存入仓库。

## 结论与依据

官方现场为 HYPE 多仓、市价、买方向、基础币单位、空数量、0%、只减仓与 TP/SL 关闭。只操作草稿和市场选择，未点击任何下单、平仓、签名、授权或资金按钮。

勾选只减仓并选择卖方向：50% 是半仓，100% 是全仓；手输超过仓位一个数量精度单位时保留输入并提示“仅减仓太大”。同方向在页面更新稳定后也显示该提示。开关切换保留数量，重新计算比例和保证金；只减仓保证金显示 N/A，顶部可用余额仍是账户数据。

限价超额和 TWAP 超额显示同样提示，TWAP 50% 也是半仓。切换 Scale 和止损市价只验证了草稿延续，没有填完所有字段或验证请求。切换到无仓位 BTC 市场，确认账户数据加载后，即使有可用余额，100% 仍不生成数量且只减仓显示不可用提示。

USDC 单位转换和50%金额输入已观察，但出现输入金额与订单价值差异；价格变化、szDecimals 向下舍入可能参与，未逆向证明所有换算细节。计划明确保留基础币最终数量不变量，不盲目复制瞬时金额值。官方部分减仓会更新强平价估算，本计划不扩展我方清算模型。

## 验证与限制

- 证据来自真实官方页面可访问性树、DOM 字段与屏幕观察；未读取账户存储或令牌。方向变化后的立即快照曾显示上一步状态，随后稳定读取确认同方向提示，不能用过早快照推断放行。
- 官方动作按钮没有原生 disabled 属性，isEnabled 不能证明可提交；本次只报告文案和表单结果，不报告签名或交易所拒绝结果。
- 一次单位选择 locator 因在局部匹配中使用 nth 索引未命中；重新读取控件结构后使用明确数量行定位成功，没有重复盲点。
- 最后恢复 HYPE、市价、买方向、HYPE 单位、空数量、0%、只减仓关闭；TP/SL 未操作。市场选择把地址变为 /trade/HYPE。用户标签页保留，未重建登录或改变账户设置。
- 只验证该多仓账户的桌面表单。没有空头账户、零可用余额持仓、手机真机、真实提交或服务端超额处理验证。无仓位市场与零余额持仓不是同一个测试。
- 本轮只新增方案/记录、更新导航和旧记录的后续链接；业务未修改，不运行应用单测、构建或真实交易回归。`pnpm memory:index`、`pnpm memory:check`、`pnpm memory:test`（8/8）、本地 Markdown 链接检查与 `git diff --check` 通过。
