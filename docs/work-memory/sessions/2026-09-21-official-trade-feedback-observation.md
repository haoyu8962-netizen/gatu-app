# 官方全部平仓反馈的实际 DOM 监听

## 背景与范围

用户要求继续监听官方终端的反馈组件，并确认操作入口为「全部关闭 → 确认市价平仓」。用户说明使用主网上专门用于测试的账户；交易确认由用户自行完成。代理通过已打开的浏览器标签只读观察通知 DOM，没有提交、签名、撤单或修改账户设置。

本次文档修改基线为 `639239c9`，分支 `codex/reviewceshi`，开始时工作区干净。沿用本任务已核对的标识；不重建缺失对话。当前项目的队列接入仍是建议，本次没有实现新的队列或更改交易代码。

## 结论与依据

- 临时观察器监听 `.toaster` 的 DOM 变更，另以 250 ms 间隔采样确认控件是否可见及通知容器替换。只保存内存样本，不读取钱包存储或应用内部状态，不请求交易接口。后段增加图标分类，但全部平仓事件发生在此前，不能声称已直接捕获该事件的成功图标或转圈动画。
- 关键相对时序如下。时间来自观察器的单调时钟，不是交易所时间或请求延迟，确认控件采样也有间隔误差。

| 相对时间 | 实际 DOM 观察 |
| --- | --- |
| 107750 ms | 「确认市价平仓」控件可见；一条普通成交提示在此之前已存在 |
| 109251 ms | 确认控件不可见，先前普通成交提示仍在 |
| 109969 ms | 新增「以市场价格下单以平掉所有仓位。」；与先前通知短暂并存 |
| 113885 ms | 先前普通成交提示移除，只剩全部平仓汇总 |
| 116979 ms | 通知容器为空 |

- 本次确认后约 0.7 秒捕获汇总通知，没有捕获新增「订单已提交」或持续进度通知。这与已核对的官方 `errorsOnly` 提交路径一致；不把有限采样表述为任何极短状态绝不可能出现。
- 汇总通知的 DOM 节点存在约 7.01 秒。当前公开脚本的成功/错误通知配置为 6 秒，通知库退出后延迟移除约 1 秒，二者相容；节点存在时长不等于实际可见时长，也不能据此推定动画实际逐帧表现。
- 监听还捕获过「订单已提交 → 买入/卖出成交」的通用通知序列，间隔约 1 秒。用户确认自己操作全部平仓，但无法将这些早于上表确认过程的提示逐一绑定到某次操作；尤其不能把确认前已存在的成交提示当成本批次的 loading 或成交阶段。买入/卖出文案本身不足以区分开仓、减仓或反向交易。
- 当前加载资源仍是 `config-DWLPMyx3.js` 和 `index-58uVNh8f.js`。公开实现中的汇总成功表示前端报告订单提交结果，不能证明每笔成交或全部仓位归零。可见逐仓进度仍属于应用层设计；这次观察没有发现持久队列。

## 验证与限制

- 浏览器通过 CUA/CDP 读取自建 DOM 观察器，成功取得上表通知新增、重叠及移除过程。此前一次旧观察器远程对象失效，无法读取；更早的网络事件缓冲出现截断，未取得可归属的交易回包。后续 DOM 捕获补足界面证据，不能替代缺失的网络响应。
- 不保存账户邮箱、钱包地址、实际交易数量/价格、盈亏、交易哈希、原始通知日志或账户截图到仓库及 `.worklog/`；表中只保留通用文案及相对时间。现有 `.worklog/close-all-queue-review-2026-09-21/` 仅有此前取得的官方公开脚本。
- 未覆盖多市场批次、部分失败、拒单、未知结果、TP/SL 清理或刷新恢复，也没有对本地 gatu 执行真实交易验收。官方通知不能证明当前账户或各目标仓位的最终状态。
- 只修改文档，没有重跑应用测试、类型检查或构建。此前 `8770d86d` 的 69 项定向测试属于原审查，不能作为本轮新验证结果。
- 本轮监听约 6 分 14 秒后主动停止，观察器返回 `active: false`，远程对象已释放；本次临时监听没有留在页面中继续运行，用户标签保持打开。
