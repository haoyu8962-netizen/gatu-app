# Earn 页：按官方文档、SDK 与官方终端实现借贷储备池

## 背景与范围

同步记录。用户先要求规划 Earn 页，“符合官方开发文档、SDK 开发文档，不确定的调试官方交易终端”；看过计划与四个待决问题后回复“不需要我排版，你只要根据文档的实践来规划……就可以开始开发”。因此四个问题按“官方文档与官方终端的做法优先，与本项目契约冲突时按契约”自行决定，取舍写入 ADR 0020。分支 `claude/earn-page`（工作树 start-dev-server-eef652），基线 `e3b5dd82`，未推送。任务 ID 未取得。

## 结论与依据

- **官方做法的来源。** 官方文档（hyperliquid-docs MCP）给出三个 info 接口、LTV、健康因子、部分清算阈值、利率模型与组合保证金规则，但没有 `borrowLend` 动作的 JSON；SDK 0.33.3 的 `borrowLend.js` 给出参数校验（`amount` 为无符号小数或 `null`）与 L1 签名。官方终端的 Earn 页在 2026-09-27 只读取证：读取 `BorrowLendPage-*.js` 与 `config-*.js` 公开脚本、调用公开 info 接口，得到 Max 规则、按钮禁用条件、清算价公式、Agent 签名、组合保证金行为、USDH 显示规则与全部英文文案；面板里的官方登录会话没有被用来提交任何操作。内置浏览器的网络面板在该站抓不到请求，WebSocket/fetch 打补丁也捕获不到（前端缓存了原始引用），所以改读脚本。
- **四个待决问题的处理。** Max 不照官方发 `null`，发送展示的精确数量并按最新状态二次封顶（确认面契约优先）；组合保证金账户手动存入、取出、借入按官方禁用，偿还也禁用（官方为卖出抵押品的兑换流程，未实现）；利息页签轮询 info（SDK 0.33.3 无订阅）；地区受限时四个操作都禁用（与官方交易状态门控、本项目地区门控一致）。
- **导航。** Earn 改为常驻一级后，1101px 未连接时法语余量只剩 6px，按 ADR 0013 的方法把窄屏阈值调到 1150。测量数据写在 ADR 0020 与 Runtime guardrails §11。
- **过程中踩到的坑。** 视图与弹窗里的文案辅助函数一开始接收 `t` 参数，Lingui 宏不转换它，卡片字段名渲染为空；改为 `msg` 描述符加显式 `translate`。数字格式响应性契约要求渲染时格式化数字的组件调用 `useNumberFormatRevision()`；通过辅助函数间接格式化的 `AssetSection`、`EarnActionSummary` 也加上，否则 React Compiler 记忆化后切换数字格式不会重渲染。
