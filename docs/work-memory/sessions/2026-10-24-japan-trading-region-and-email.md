# 日本改为允许交易地区与日本用户营销邮件草案

## 背景与范围

- 同步记录。2026-10-24 用户（运营方）在 Claude Code 桌面会话里要求「为这个项目撰写一个面向日本用户的群发邮件模板，根据产品特色与营销点做出最好的邮件」。会话任务 ID 未取得（`thread: null`）。工作树分支 `claude/japan-user-email-template-d3e2b5`，基线 `main` `9ccb88c0`（与线上 p32 相同）。
- 起步核查发现：`apps/terminal/src/config/geo.ts` 把 `JP` 列为禁止交易地区（注释写明是首发配置留下的，不在条款 §2.2）；隐私政策 §3 没有营销邮件用途；终端没有日语界面。Agent 用选择题请运营方定方向，运营方回答「日本应该被列为允许交易地区」。
- 影响面：地区判定配置与一个新测试；ADR 0042；`docs/marketing/jp-launch-email/` 四个文件；CHANGELOG、文档地图、ADR 索引、工作记忆话题 `jurisdiction-marketing`。

## 结论与依据

- 地区：从 `TRADE_RESTRICTED_COUNTRIES` 删除 `JP`，条款点名地区、制裁地区与代理拦截不变（[ADR 0042](../../adr/0042-japan-allowed-trading-region.md)）。新测试 `geo-restriction-list.test.ts` 钉住完整清单并断言 `JP` 不受限。
- 邮件的做法：Agent 用两轮多代理工作流完成。第一轮并行调研产品可宣传的事实（逐条对照仓库证据）、日本法规（特定電子メール法、景表法、金商法与資金決済法）和日本加密交易者与邮件惯例，再写三套不同主张（自托管、专业工具、易上手）由读者、转化、合规三位评审打分；三位都选「自托管・預けない」（7.5、8、6.5 分）。第二轮由一位撰稿人合并获胜方案与评审嫁接建议，四个视角（日文文案、合规、事实、邮件工程渲染）审阅两轮并修订。之后主会话做第 3 轮编辑精简（正文约 2,000 字太密，主按钮在 600px 宽时约 3,700px 处），再由三个视角做只报必须项的独立复核。
- 法规调研的核心结论（Agent 的网页调研，不是法律意见；来源与日期见邮件 README 第 8 节）：未在日本登记的 Sairn Corp. 用日语向日本居民推广按成交收费的永续合约交易界面，很可能构成无登记业者的「勧誘」；金融厅判断境外网站时看取引防止措置，删除地区限制正好拿掉它。因此 ADR 0042 建议取得律师书面意见前不发布，邮件 README 把律师的书面批准列为第 1 道发送闸门。
- 刻意不写的卖点（KYC 不要、杠杆倍数、股票与指数永续、银行卡入金、自动存款、返佣、Earn、竞品名称、日语支持等）和理由列在邮件 README 第 5 节。

## 验证与限制

- 代码（本分支工作区，2026-10-24）：`pnpm --dir apps/terminal exec vitest run` 地区相关 5 个文件 28 项通过；把 `JP` 加回清单的变异让新测试 2 项失败，已还原；`pnpm exec biome check` 两个改动的 TS 文件通过；`pnpm --filter @sairn/terminal typecheck` 退出码 0；`git diff --check` 通过。没有跑全量终端测试。
- 邮件：脚本逐句对照纯文本与 HTML 可见文字，除费率表写成列表外一致；禁用词检查零命中；HTML 51,350 字节（低于 Gmail 约 102 KB 截断线）。用仓库的 Playwright 无头 Chromium 在 640px 与 375px、浅色与深色渲染并查看截图，375px 下 `scrollWidth` 等于视口、无横向溢出。这不是邮件客户端测试：Gmail、iOS 邮件、Outlook、Yahoo!メール与日本运营商邮箱都没有测（邮件 README 第 6 节列有 QA 矩阵）。Chromium 在本机沙箱里启动失败（mach port 权限），截图在沙箱外运行。
- 第 3 轮独立复核（日文文案、合规、事实与同步三个视角，只报必须项）发现主会话精简时引入 3 处文案错误：把 builder fee 批准时机写成「ビルダー手数料の対象となるご注文」（`requiresBuilderFee = !twapOrder`，现货买入也会触发批准）、删掉了中和「邮箱存款免 gas」暗示的一句、删掉了「受け取り」（提款方向）；另把小标题写成与下文矛盾的「アプリ」；以及若干 README 引文未同步。全部已按复核意见改正，改正后没有再做一轮独立复核，改正本身由主会话的逐句对照与禁用词检查覆盖。
- 未做：日本律师意见；隐私政策与个人信息保护法相关修改；opt-in 同意的收集与记录；发送基础设施（独立子域、SPF/DKIM/DMARC、一键退订）；`{{company_address}}` 等占位符；ADR 0042 的发布与真实日本 IP 验收；任何真实发送。
- 本地证据：截图与生成脚本在会话的临时目录，不进仓库；工作流各代理的返回值只在本机会话目录。

## 追加：第 4 版利益导向重写（2026-10-24，同一会话）

- 运营方看过第 3 版后要求：正文不必提 builder fee；营销邮件要从用户的收益与需求出发，而不是介绍产品机制；发邮件成本高，要尽一切办法提高转化率。
- 主会话据此重写为第 4 版：首屏是眉标题＋新闻大标题＋利益说明＋按钮（手机上第一个按钮在约 490px 处，第 3 版约 3,100px）；四个特点各用「利益标题＋一句证据」（资产不托管、100 以上的币种 24 小时、手续费数字、专业工具与手机）；三步上手里写出英文界面上的按钮名（「Connect」「Deposit」）与 10 美元起的最小下单额；全文三个点击入口指向同一落地页。正文不再出现 builder fee；页脚保留一行费用披露，术语改为「Sairnの手数料」。README 新增「第 4 版：利益导向重写」「转化率方案」（投递率、人群分层、日语界面与日语存款指南、iCloud 专用代理、主题测试、未打开者补发、发送时间、转化事件埋点、刻意不用奖励与限时手段）并改写后续邮件编排为行为触发序列。
- 复核：一轮工作流（README 同步→转化、合规、事实三视角→修订）提出 23 条意见，修订者落实 14 条必须项。合规视角指出「登録はメールアドレスだけ」会被读成不用本人确认（等于变相宣传 KYC 不要），改为「ウォレットをお持ちでない方も、メールアドレスで登録できます」；「資産を預けずに」改回「運営会社に預けずに」；去掉「いつでも」「すぐに」「新しい銘柄も自動で追加」（后者会带入未审核的第三方股票、指数永续）。主会话随后采纳转化视角的数字费率小标题，把「这是在 Sairn 交易的合计费率」这条限定用正文字号紧贴在下面，并修了 320px 宽时的横向溢出（真正撑宽的是不换行的费率小标题），之后请一个独立代理只就这处费率改动做对抗式复核：限定语紧贴在标题下、用正文字号，满足打消し表示的近接与醒目要求，没有必须修改的缺陷；日文与中文对照也没有必须项。它的可选建议（小标题加「無期限先物の」）未采纳，因为紧接的第一句已经写明范围，标题加长会在手机上折成三行。它同时提醒：免责文字消除不了无登记业者招揽的风险，只有律师闸门能解决。
- 检查：逐句对照、禁用词、日文与半角之间的空格、半角片假名都是零；无头 Chromium 下 320、375、640px 页面宽度都等于视口（320px 去掉 `<style>` 也是）。仍然不是邮件客户端测试。

## 追加：官网 sairn.ai 审计（2026-10-24，同一会话）

- 运营方问「现在缺什么、官网要不要重做、现在是什么样式方案」。三个只读审计代理（样式系统、内容与日本活动、日本落地页实践）加主会话用内置浏览器查看线上首页，结论一致：
  - 样式方案：Astro 5 静态输出 + Tailwind v4；从 `@sairn/ui` 裁剪的令牌内联在 `apps/website/src/styles/global.css`；只有深色，底色仍是旧的海军蓝 `#12131a`（终端与品牌是 `#0F1A1F`）；Inter Variable + Instrument Serif；参照 midday.ai 的单栏分节；无前端框架，只有内联脚本。最后一次实质改动是 2026-10-01 的品牌切换，2026-10-02 发布。
  - 不需要推倒重做：技术栈适合落地页。问题在内容与缺页：线上首页写着「No KYC」、股票与日经 225 永续、满杠杆、12ms，截图带杠杆倍数，与邮件第 5 节冲突，而邮件把 sairn.ai 列为官方网址；没有任何多语言能力（`lang="en"`、无 hreflang、`/ja/` 返回 404）；两种字体都没有日文字形；没有日语存款指南、订阅同意入口与归因；官网的 `/privacy/` 是同一份法律文本的另一份手动发布。
  - 小缺陷：`text-fg-weak` 没有对应令牌（法律页正文是纯白）；`.reveal` 在无 JS 时不可见；theme-color 三处不一致；`tailwindcss` 与 `@tailwindcss/vite` 版本不一致；空博客与「coming soon」。
- 已把「官网与邮件是否矛盾」写进邮件 README 闸门 1 的律师问题。官网文案与 `/ja/` 页都没有改，待运营方决定。
- 线上检查范围：内置浏览器在桌面与 375px 宽读取首页文字、截图与运行时指标；手机首屏截图时标题短暂空白，约 2 秒后出现，是入场动画，不是缺陷。
