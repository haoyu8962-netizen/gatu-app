# 下单布局：自然高度、TWAP 与双端表单

## 背景与范围

用户多次对比 Hyperliquid，指出移动 TWAP 内部滚动、选项错位、TP/SL 输入框过高，以及桌面下单表单的内部滚动。按议题整理 2026-09-11 至 09-12 的变更；具体交互规则以当前专题文档为准。

## 结论与依据

- 移动下单区使用视口最小高度，内容自然增长；订单簿延伸至相同底边，账户区在后。页面负责纵向滚动，不再以固定分屏高度迫使表单内部滚动。
- 桌面内容不能反向改变用户网格几何；默认布局容纳八种普通订单类型，约束较小的用户布局仍保留受控内部滚动。不能把移动规则机械复制到桌面。
- TWAP 数量在运行时间之前；随机化与只减仓同组，触发价及买卖方向对应的最高/最低价归入默认关闭的高级设置。
- 关闭高级设置时保留输入草稿，但从验证、摘要、确认及提交中排除隐藏价格；不能只通过 CSS 隐藏。
- TP/SL 双端输入框 33px、标签常驻、单位菜单各自独立。数量、计价单位与只减仓使用共享草稿，响应式切换不能丢失输入。
- 紧凑标题、选项触控范围与留白使用容器实际宽度；空余高度放在摘要前，不能随机扩张字段间距。

## 验证与限制

上述是提交与当前规范核对后的历史总结。本次未重新运行浏览器或真机下单测试；既有 PR 浏览器运行不能当成所有手机真机验收。后续调整需分别验证桌面默认/受限尺寸、移动展开/折叠及响应式草稿保留，不发送真实交易。

## 后续与替代关系

“切换订单类型必须保持移动分屏固定高度”是已被自然高度规则取代的早期约束，不能从旧讨论恢复。后续以专题规范、当前 AGENTS.md 与代码为准；记录具体尺寸、状态和失败证据。
