# 建立可追溯工作记录与定期索引

## 背景与范围

用户要求在工作目录保存工作过程，按议题或时间总结过去任务，并定期维护可检索索引；随后明确要求执行。基线为 `422ea8a6`，任务开始时工作区干净。

本次保存可见记录、动作线索、证据及简明决策依据，不保存或重建内部推理。六个历史议题采用事后整理标记；当前任务是同步工作记录。未更改交易功能、服务器状态或部署配置。

## 结论与依据

- 本地 `.worklog/` 保存经过白名单过滤和脱敏的 JSONL 事件及 manifest，保持 Git 忽略。原始应用会话仍在本机源目录，没有把摘要伪装成完整原文。
- tracked 任务摘要使用一个 Markdown 文件内的 JSON 元数据，避免正文和独立数据库双份更新；Node 标准库即可完成校验和索引生成，没有新增依赖。
- 不把会话流水塞进 AGENTS.md，改为稳定检索规则及文档入口；现有专题规范继续定义当前架构。
- 首批议题是 PR 复审、双端下单、行情恢复/价格来源、Vite 缓存、账户资金、配对发布；当前维护机制另有本条记录。
- 索引检查引用、提交、状态和替代关系，使用稳定排序且不写生成时间。原子替换只防止半文件，提交前仍需保证没有并发写入并重新校验。
- 已创建本地每周一 09:00（Asia/Shanghai）维护任务“整理 Sairn 工作记忆”，自动化 ID `gatu`，关联当前任务。工具确认 ACTIVE，并核对本机保存的 heartbeat、时间规则及目标任务。首次定时执行尚未发生；离线和应用不可用会影响本地调度。
