# 存款弹窗后续：状态屏与切换网络屏并入同一滚动结构，补 WebKit、扫码解码与包体预算测量

## 背景与范围

同步记录，2026-10-05（本地时间 00:20–01:30 前后），与[存款弹窗重排](2026-10-04-funds-dialog-layout.md)同一会话、同一分支 `claude/sync-code-start-dev-08b8d0`，未推送。用户的原话是「请继续一下任务」，并列出五项：真实手机的触摸滚动、软键盘和扫码；「真实存款已通过」；生产构建和包体预算测量，推送前应量一次；同一弹窗的状态屏和「网络错误」屏是独立组件，没有用新的滚动结构；五种外语的新提醒译文没有母语者审校。未取得任务标识。

第二项是用户告知的结果，本会话没有做真实或测试网存款，也没有看到那笔存款的记录。

## 结论与依据

状态屏与切换网络屏（`718618fd`）：

- 滚动结构的四个常量移到 `lib/ui/funds-modal-scroll.ts`，`FundsModalShell`、`StatusScreen`、`WrongNetworkScreen` 三处共用：弹层 `!overflow-hidden`，头部 `shrink-0`，内容区 `min-h-0 flex-1 overflow-y-auto overscroll-y-contain` 并隐藏滚动条，内容区带 `data-slot="funds-modal-body"`。
- 两个屏原先各自带 `overflow-y-auto` 的弹层整体滚动，矮视口下关闭按钮会被滚走；改后只有内容区滚动。

译文（`47510cc0`）：没有母语者可用，做法是把新提醒里的术语与同一语言目录里已有的写法对齐（法语冠词与「d'autres réseaux」、印地语「अन्य संपत्तियां」、中文句末「将不会存入交易账户。」）。这是一致性修正，不是审校。

源码契约 `funds-modal-scroll-contract`（`5d95d317` 到 `91f4189b`）：

- 改为用 TypeScript 解析语法树。登记的三个文件只接受一种写法：一个弹窗原件元素，子节点恰好是一个 `ModalHeader` 后跟一个 `ModalContent`，三个标签是文件里出现这些名字的全部位置，不带展开属性或 `children` 属性；类与 `data-slot` 必须以共用常量开头；常量与 `cn` 必须是各自模块的不带别名的导入且未被遮蔽；全文不得出现 `overflow-` 或 `scrollbar`。
- 存款流程的范围由 `deposit-modal.tsx` 与加载回退沿导入、再导出和字面量运行时加载遍历得到（当时 164 个文件），到 `pending-action-modal.tsx` 为止。范围内任何能到达弹窗原件的文件必须是登记的三个之一。相对或 `@/` 名称解析不到 `src` 下的源码或已存在的资源时测试失败，不跳过。
- UI 包 `modal.tsx` 与 `drawer.tsx` 的每个值导出必须被分到 surface / part / inert 之一，新导出未分类时测试失败；读不懂的导出写法（默认导出、`export *`、命名空间、枚举等）直接报错。UI 包其他文件能到达弹窗实现（这两个模块或入口、Base UI 的 dialog / alert-dialog / drawer，或读不懂的名称）、包内出现子目录、入口不全是不带别名的 `export { … } from` 列表，都会失败。模块一律按解析后的文件比较，不按说明符的写法。
- 规则与界限写在 `.claude/rules/style-ui-guide.md` 的 Dialog chrome 一条：数源码元素、不数循环实例；看不到 UI 包以外的包导出的原件，也看不到不用这些原件自建的弹窗；只读类列表开头的常量；不证明计算样式，计算样式由浏览器测试测量。

这一段没有照「逐个补洞」做到底的原因：审查方每轮都能在词法规则上再找到一个绕过写法，第 7–10 轮连续停在 8.3–8.5。改为「只认一种写法、读不懂就失败」后，剩下的发现集中到模块解析的边角；再把所有模块比较改成按解析后的文件身份，第 14 轮不再有发现。

## 同日后续：模拟器上发现并修复「关闭按钮压住滚动内容」

用户在模拟器面板里允许访问后（原话「允许访问了 请你继续」），在 iPhone SE（第 3 代，iOS 18.1 模拟器，375×667 点）的 Safari 里打开浏览器夹具 `account-actions.html?surface=funds`（真实的 `FundsModalShell`、`DepositForm`、`WithdrawForm`，不经过登录）。输入路径是模拟器注入的触摸，不是手指。

- 触摸滚动：邮箱存款表单在这个尺寸下溢出，内容区可滚到底，关闭按钮位置不变，没有可见滚动条。
- 发现的缺陷：内容区滚到中间时，右上角关闭按钮压在滚上来的文字上（「Minimum 0.4 USDC」被 ✕ 盖住）。原因是外壳的固定头部只有 28px（桌面 24px）高，而绝对定位的关闭与返回按钮向下伸到 52px（桌面 56px），伸进了滚动区；此前的浏览器测试只比较按钮位置不变，没有检查按钮下方是什么。真实 iPhone 的 Safari 有工具栏，可视高度比测试视口矮，所以这个状态在真机上常见，不限于 SE。
- 修复：每个表单的标题成为表单根节点下的整宽块，带 `FUNDS_MODAL_HEADING_CLASS`（`sticky -top-3 z-1 bg-modal`）吸在内容区顶边，内容从这条带下面滚过。吸顶偏移从内容区内边距算起，所以带上移 `-top-3`，位于最前的标题再用 `-mt-3 pt-3` 盖住上方的内边距；标题另加等于表单间距的下内边距并用同值负外边距抵消，使带高于按钮而静止布局不变。外部钱包存款表单的图标在标题之前且居中，只把标题与副标题做成吸顶带。四处：邮箱存款、外部钱包存款、提款、方式选择。
- 没有采用：把头部加高到容纳按钮（静止时标题下移 16–24px，桌面上标题不再与关闭按钮同一行）；给按钮加不透明底（滚过的金额会被按钮截掉一截）；把可见标题移进头部（要改四个表单与其测试及弹窗的可访问名称，范围过大）。
- 浏览器测试：`expectFundsDialogScroll` 新增逐个滚动位置（8px 一步）用 `elementsFromPoint` 检查固定控件下方，内容区里只允许标题带或包含标题带的容器，且标题带背景须等于弹层表面色；新增用例对四种表单在 375×260、375×666、1363×260、1363×852 下执行。修复前这条断言在 10 个用例上失败；修复后 Chrome 36 项、WebKit 资金相关 18 项通过；4 个变异（带停在内边距处、去掉底色、不吸顶、外部钱包表单去掉标题带）全部被抓到。当时夹具的外壳没有返回按钮，这个缺口随后被复审指出并补上（见下一小节）。
- 模拟器复验（修复后）：修复前后两张静止状态截图里，标题、步骤、资产与网络、二维码的纵向位置读数相同（目测比对，不是像素差分）；滚到此前出问题的位置，标题留在原位，上方内容从标题带下滚过，关闭按钮下没有文字；关闭按钮可点。
- 软键盘：点提款表单的金额框，弹出小数键盘（数字与小数点），页面把输入框移到可见处，头部与关闭按钮可见；在键盘上点 2、.、5，输入框显示 2.5；点「完成」收起后弹层回到原位置，净到账显示 $2.30。观察到的现状：键盘打开时弹层下半部分（手续费行与提交按钮）在键盘后面，拖动只能平移约 12 点，需要先收起键盘才能点提交按钮。这是底部弹层原件对键盘的既有处理，本次没有改，也没有在修改前的版本上对照测过。
- 仍未做：真实手机上用手指操作；相机扫码（模拟器没有相机）；读屏。

### 对修复提交的复审与返回按钮回归

- 包体预算（`4d6aa905`，同一口径）：总量 3,297,321，上限 3,297,651，余量 330 字节；交易页启动 1,632,653，手机运行时 118,509，桌面运行时 202,504，构建以 0 退出。
