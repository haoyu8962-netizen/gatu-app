# 订单簿新增档位动效实施方案

## 状态与结论

分组隔离修复须遵守[官方依据与修复方案](terminal-review-remediation.md)：公共 `l2Book` 帧没有分组身份，不得用请求 key 或退订 ACK 推定旧流已排空。不同分组使用有连接限额的独立 transport，首个有效快照保持静默。

2026-09-08 先完成参考调试、项目接入审查和本方案，再修订 `AGENTS.md` 与布局契约并实施。桌面、移动端完整双栏及紧凑订单簿现已接入同一事件控制器、Hook 和覆盖层；验证范围见文末记录。

采用「完整有效实时快照差分 → 短期动画事件 → 共享整行覆盖层」方案。桌面订单簿、移动端完整双栏、移动端紧凑双边及单边模式共用事件规则和动画组件。默认启用，遵从系统 `prefers-reduced-motion`；设置中的「订单簿动画」使用现有全局设置持久化布尔偏好，同时控制新增价位背景和数量文字变色。

它表达的是「当前行情数据流中新观察到的价格档位」，不是成交、数量增加或全球新挂单的证明。尤其五档、二十档数据流中，原有深档位进入订阅窗口也可能触发。界面不增加解释文案、提示图标或提醒条。

## 已核实的参考机制

来源：[Hyperliquid HYPE 交易终端](https://app.hyperliquid.xyz/trade/HYPE) 的动态 DOM、动画计算样式及本次加载的[公开前端资源](https://app.hyperliquid.xyz/assets/index-NcPTmdxW.js)。资源文件名随版本变化，以下记录本次观察，不作为其永久接口。

| 项目 | 本次核实结果 | 本项目决定 |
| --- | --- | --- |
| 触发 | 本帧价格不在上一帧价格集合；初始无比较基线时静默 | 在完整可用快照上比较，买卖两侧分别识别 |
| 背景层 | 整行宽度，位于深度条之上、文字之下，不接收指针 | 共享绝对定位覆盖层，不改变行布局 |
| 时间 | `800ms ease`，透明度 `0 → 0.7 → 0`，峰值位于 20%，播放一次 | 采用同一时间曲线，不循环 |
| 错峰 | 档位索引映射 `[0,8,4,3,2,5,7,1,9,6] × 50ms` | 使用触发时固定的可见位置索引，延迟 0～450ms |
| 深色背景 | 买盘 `#1E5D52`，卖盘 `#732A36` | 作为深色脉冲目标色；先完成文字对比度前置工作 |
| 原有深度 | 独立色块，按累计深度改变宽度 | 保留本项目现有累计算法、0.15 透明度与方向 |

参考的错峰时间窗保存在按行索引复用的组件中，覆盖层由后续渲染检查时间后挂载；实测同一覆盖层可能跨越行内价格变化，且会受刷新时机影响提前结束。本项目按 `side + price` 保存独立事件，用 CSS 延迟与单调时钟维持剩余时长，不复制参考的按行复用行为。两者采用相同颜色与曲线，但不承诺逐帧相同。

参考将两侧价格合并比较；本项目采用 `side + price`，避免买卖方向之间错误复用历史。本次没有验证参考的浅色实现，不推断其浅色配色。

## 数量动画与用户开关修复契约

先定义以下契约，再修改实现：

- 修复数量由 `10 → 11 → 11` 时第三次渲染移除动画的缺陷。将已提交数值变化对应的方向和播放身份保留到结束；同值刷新、显示格式或主题变化不得重启或中断 1.8s 渐隐。连续有效数值变化每次重新播放，结束后恢复普通文字。
- 数值比较继续使用现有 Big.js 辅助函数；等价十进制表示不产生新事件。市场/分组身份改变、关闭动画时取消旧反馈并建立新基线，重新开启不得补播。
- 在桌面与手机共用的设置弹窗「显示」中新增「订单簿动画」开关，默认开启。沿用 `use-global-settings-store` 的校验与持久化；旧设置没有该字段时保持开启，已保存的关闭值刷新后仍有效。切换立即生效，不刷新页面或重挂载报价按钮、图表及下单输入。
- 关闭时同时取消整行背景和数量文字变色，保持静态价格、深度条、行情订阅和选价功能。重新开启背景后以当前有效快照建立静默基线，仅后续新增价位播放。系统减少动态效果优先于开启偏好。
- 桌面、移动完整双栏与紧凑单双边模式共用偏好；移动双栏累计 Total 继续保持静态。设置名称及可访问名称随语言热切换，补齐六种语言。
- 回归覆盖同值重渲染保留、连续增减重启、结束清理、等价小数、身份重置、开关即时取消/重新开启静默、设置持久化兼容、减少动态效果与真实浏览器三种布局。颜色、背景 800ms 曲线和订单簿几何不变。

## 一、事件判定与静默边界

### 数据身份

比较上下文由 `network + coin + grouping + actualFeedSource` 组成。来源必须区分 `l2`、`l2Book-fast` 和 `l2Book-full`，不得复用缺少网络、来源维度的桌面 `flashResetKey`。

输入只接受经过现有身份、新鲜度及状态检查的实时快照。移动端使用 `currentLiveBook`，不使用合并缓存回退后的 `book`。`l2` 已提供重建后的完整档位快照，无需另行解码增量或新增订阅。

纯辅助函数比较该输入的全部买卖价格集合，然后才按可见档位筛选动画。这里的「完整」是当前来源实际提供的全部档位，不要求将紧凑订阅升级为全量行情。

价格身份使用 Big.js 规范化的十进制字符串，使 `83.950` 与 `83.95` 等价；不使用显示后的格式化价格或 JavaScript 浮点数。原始 `px/sz`、选价值和金额计算路径保持现有数据类型。

### 触发规则

- 同一上下文中，连续有效实时快照新增的 `side + price` 才产生事件。同价数量、累计量或排名变化不产生整行事件。
- 首次有效快照只建立基线。某侧为空时清除该侧基线；该侧重新出现后的第一份有效数据也只建立基线，避免恢复时整侧闪动。
- 新事件仅允许在创建时已经属于当前完整可见档位的价格播放。离屏或隐藏侧不排队，不在扩大面板、切换模式后补播。
- 行情重新排序使档位退出完整可见集合时，也丢弃该档位的动画事件；完整快照比较基线继续保留，不能在它重新进入视区时补播。
- 档位删除时删除对应事件；在连续有效快照内再次出现时可以创建新事件。未删除的同价档位不能因普通更新重播。
- 语言、显示单位和主题变化不产生价格事件；不把这些展示状态写入价格 key。

| 状态变化 | 处理 |
| --- | --- |
| 网络、市场、分组、实际来源改变 | 取消事件，清除比较基线，新的首帧静默 |
| 缺失、错误、过期、缓存回退、断线后恢复 | 取消事件，恢复后的首份有效实时快照静默 |
| 切离订单簿、页面隐藏、面板离屏 | 取消待播及在播事件，恢复可见后重新建立基线 |
| 紧凑单双边切换、完整/紧凑切换、可见行容量改变 | 取消旧视图事件，当前有效快照作为新视图基线，不能把多显示出的旧价格当成新增 |
| 尺寸变化但可见行容量不变 | 不生成事件、不重启延迟；已有覆盖层跟随同一行的实际尺寸 |
| 系统减少动态效果开启 | 取消事件并停止创建动画；关闭后的首份实时快照静默，不恢复旧动画 |
| 占位、骨架、未测量或不可交互数据 | 不创建覆盖层，不播放动画 |

沿用订阅层断线时设置的 stale 状态处理重连，不为视觉效果增加协议层重连计数或修改账户、签名、行情可用性规则。

## 二、React 接入与动画生命周期

新增纯差分模块 `lib/trade/orderbook-new-levels.ts`、展示控制器 `lib/ui/orderbook-level-pulses.ts`、共享 Hook `hooks/trade/use-orderbook-level-pulses.ts` 和组件 `components/trade/orderbook/orderbook-level-pulse.tsx`。控制器只拥有历史价格集合和短期事件，不保存第二份完整行情，不使用全局或持久化 store。

1. 桌面在 `OrderbookPanel` 使用一次 Hook，输入有效原始快照、有序的完整可见价格键及完整上下文。可见资格依据已测量的 `fullRowCount`，不能使用未测量时的默认行数；显示索引用于冻结错峰延迟，包含卖盘反向排列的情况。价格差分不以 `processLevels(..., visibleRows)` 的输出作为历史基线。
2. 手机由 `MobileBookView` 筛选并传递实时动画输入；`CompactOrderbook` 或 `SplitOrderbook` 在已有行数测量处各使用同一 Hook 一次。这样能就地给出可见价格集合，不把子布局高度提升到父级形成测量反馈，也不增加行情订阅。
3. Hook 通过 Effect 将已提交的输入同步给面板级控制器，订阅使用 `useSyncExternalStore`。差分算法本身保持纯函数；时间、ID 分配与浏览器定时器只在提交或清理阶段操作。render、`useMemo`、`getSnapshot` 内不推进历史、不分配事件、不读取当前时间。
4. 控制器保存 `{ id, side, priceKey, createdAt, delayMs, expiresAt }`，对外快照附带上下文及视图身份，便于即时门控。普通行情只推进价格基线；仅新增、移除、取消事件时通知订阅者，且没有变化时返回同一个快照引用。不得每帧镜像行情再触发第二轮 React state 更新。SSR 使用稳定的空事件快照，客户端提交前也不创建动画，避免水合差异。
5. 使用单调时钟 `performance.now()`；到期时间为创建时间加固定延迟及 800ms，不根据交易所时间或用户系统时间判定。每个面板最多一个最近到期清理计时器；`animationend` 可提前清理，回调需核对事件 ID，不能删除后来同价的新事件。
6. 仅为覆盖层使用事件 key。报价按钮仍使用现有价格 key，保留 DOM、焦点、长按提示和原有数量文字节点。`OrderbookRow` 的自定义 memo 比较必须包含事件身份。
7. 后续高频快照不截断 800ms 动画，也不更新已开始事件的错峰索引。事件以时间戳为准；提交时计算 `animation-delay = createdAt + delayMs - now`，允许负值以接续正确进度，不能归零后从头补播。若 `now >= expiresAt` 则不启动并按 ID 清理。正常挂载应完整播放；延迟挂载只播放尚未结束的部分。
8. 隐藏、视图和上下文变化需在渲染门控中立即屏蔽不匹配事件，并清理控制器。异步计时器、可见性监听、订阅在卸载时清理；Strict Mode 的重复 Effect 不重复发出事件，清理后再次 setup 必须能重新建立基线，不能永久关闭同一控制器。

每次提交实时快照前，读取已经创建的媒体查询对象和当前页面可见性来刷新环境门控；不额外测量行或面板。浏览器可能先改变 `matches`、后发送 `change`，迟到的同值通知不得清除已经建立的恢复基线。已断开的观察器回调也不得改变新面板的可见状态。

不用逐帧 React state、逐行计时器、逐行 ResizeObserver、永久 `will-change`，也不同时引入 CSS 与 Web Animations 两套播放机制。可见性检测在面板级进行，保留现有尺寸测量职责。

## 三、层级、配色和可读性

绘制顺序固定为：行底色/悬停 → 深度条 → 整行脉冲 → 数字文字和焦点反馈。覆盖层使用 `absolute inset-0`、`pointer-events:none`、`aria-hidden`，只改变透明度。它随已有自适应行高铺满当前行，不写死 23px/24px，不更改深度宽度、间距、排名偏移、滚动或网格尺寸。

保留数量文字原有 1.8s 单次变化的触发语义、时长与恢复逻辑；新增背景事件独立于该动效。手机完整双栏的累计 `Total` 继续为静态文字，不按单档数量着色或启动文字动画。

**颜色前置必须与本功能一并完成。** 当前价格、深度共用颜色；原样叠加参考背景后，深色价格最差约为买盘 2.86:1、卖盘 3.73:1，浅色可接近 1:1。现有数量变化起始色也不能满足全部叠层组合。因此，不能只新增两个深色 CSS 值后开启效果。

- 按[前次颜色审查方案](orderbook-ui-reference-audit.md)分开价格文字与深度图形的语义角色，新增 `--orderbook-price-bid/ask` 和 `--orderbook-level-pulse-bid/ask`。
- 保留深度和模式图标的现有 token、深度透明度及移动镜像方向。颜色修改限制在订单簿，不修改全局涨跌色。
- 保留数量闪动 token，明确其代表「数量增加/减少」，不能误作买卖方向；按深浅主题分别选择色值。买盘行也必须验收数量减少色，卖盘行也必须验收数量增加色。
- 统一可读的静态数量与表头前景，包含紧凑订单簿；调整订单簿专用悬停背景，避免通用悬停色破坏对比度。
- 实施前同步修订 `AGENTS.md` 中「价格与深度共色」及固定数量闪动色两处契约，再改 token 与测试。保留 1.8s 行为契约，不通过取消数量动效来规避问题。

实现采用以下主题色板，通过实际 `styles.css` 的合成颜色测试，并在浏览器中检查脉冲峰值与焦点显示：

| 角色 | 深色买盘/增加 | 深色卖盘/减少 | 浅色买盘/增加 | 浅色卖盘/减少 |
| --- | --- | --- | --- | --- |
| 整行脉冲 | `#1E5D52` | `#732A36` | `#ABD8C9` | `#F4C3CB` |
| 价格文字 | `#27D29F` | `#F08B9E` | `#056445` | `#A62B2B` |
| 数量变化起始色 | `#27D29F` | `#F4A4B3` | `#056445` | `#A62B2B` |
| 深度条与视图图标 | `#1FA67D` | `#ED7088` | `--text-success`（`#067A57`） | `--text-error`（`#C73A3A`） |

深度条与视图模式图标共用 `--orderbook-depth-bid/ask`：深色为固定色值，浅色解析到 `--text-success`/`--text-error`。两套主题均为实色填充、透明度 0.15，不使用渐变；横向占比与对齐方向见[行几何](orderbook-layout.md)。颜色修改限制在 `--orderbook-*` token 内，不改全局涨跌色，且仍须通过本节末尾的组合对比度验收。

深色前景按参考深度色的 HSL 色相和饱和度校准，色号取整后仅有微小误差；增加亮度以满足完整叠层对比度，并为 4.5:1 门槛保留余量。买盘价格/数量采用约 162° 的绿，卖盘价格/数量采用约 348° 的红。数量减少色需要同时适用于较亮的买盘脉冲底，因此比仅用于卖盘的价格色略亮。桌面、移动完整双栏和紧凑模式继续读取同一组 token，不按设备分配色值。

此前的 `#83D1B9 / #FF9C9C / #FFADAD` 满足可读性，但明显降低了绿色饱和度，并将红色移向 0° 色相，造成浅绿、浅粉感。深色前景校准只涉及价格和数量变化的四个前景 token；参考脉冲背景、深度条、透明度、时长、文字大小与交互保持原规则。

浅色脉冲使用 `#ABD8C9 / #F4C3CB`，在原有绿、红色相基础上加深背景，同时保留深色价格及数量文字。旧背景 `#E3F2ED / #FBE9EC` 在白底上的 0.7 峰值仅为 `#EBF6F2 / #FCF0F2`，接近白色，叠到已有深度条上还会使该区域变浅；新背景对应 `#C4E4D9 / #F7D5DB`，可在整行及深度区域形成一致的加深反馈。桌面、移动完整双栏与紧凑订单簿只读取共享浅色 token，峰值 0.7、800ms 曲线、0.15 深度透明度和深色主题保持原规则。浅色主题为项目独立适配，不将其声称为参考终端的浅色实践。

浅色静态数量使用 `#344054`，深色使用 `#D2DAD7`；表头分别使用 `#526174` 与 `#949E9C`。订单簿专用悬停层分别使用 `#0015800A` 与 `#FFFFFF08`。小字号价格、数量、累计量、表头对比度至少 4.5:1；回归覆盖背景透明度 0～0.7 的全过程、有无深度、悬停、数量两种变化颜色及其 sRGB/OKLab 完整恢复过程，不能只测正常底色或动画峰值。以后修改相关 token 时仍须通过这些组合检查。

## 四、实施顺序与验收

1. 文档与颜色前置：同步颜色契约和布局文档；落实专用 token，并补齐组合颜色测试。
2. 纯差分与短期事件控制器：验证身份、静默边界、时间和清理机制。
3. 桌面、手机完整与紧凑模式接入共享覆盖层，保留原有订阅及行几何。
4. 使用固定行情的真实组件浏览器夹具验收，再以 3006 开发页面观察实时效果。夹具使用[独立 Vite 缓存](runtime-guardrails.md)，不影响应用开发服务器。

| 回归范围 | 必须通过 |
| --- | --- |
| 价格差分 | 首帧、等价十进制、数量/累计量/排名变化均静默；仅新增价格触发；买卖隔离；删除再出现；空侧重建 |
| 生命周期 | 正常挂载后连续 100ms 更新不截断或重播；延迟挂载以负延迟接续，过期不播放；乱序清理回调、卸载、Strict Mode 无重复与泄漏；SSR 水合一致 |
