# 下单面板：桌面与移动端对照

参考页面：[Hyperliquid HYPE](https://app.hyperliquid.xyz/trade/HYPE)。2026-09-11 实测桌面 1440×1000、移动端 375×666 与 320px 窄屏；本项目同时验证 1001px 紧凑桌面边界。比较范围是界面、字段交互与草稿状态，没有连接新钱包、签名或提交真实交易。

## 发现与处理

| 功能块 | Hyperliquid 实测 | 本项目修改前 | 本次处理 |
| --- | --- | --- | --- |
| 止盈止损输入框 | 双端约 33px；价格与收益左右配对 | 桌面 33px、手机 44px，单位控件扩展区域可能遮挡输入 | 双端统一 33px；价格、收益都有常驻标签；每行独立单位菜单 |
| 普通输入 | 双端约 33px | 桌面 36px、手机 32px | 保留现有普通输入密度；手机输入文字保留 16px，避免依赖缩放 |
| TWAP 字段顺序 | 数量、比例、时间、随机/只减仓、高级设置 | 双端已调整主要顺序，但摘要仍分叉 | 复用同一时间表单和摘要；选项同组，窄容器换行 |
| TWAP 高级设置 | 默认收起；展开触发价与最高/最低价 | 已有开关和有效值过滤 | 保留草稿；关闭后校验、摘要、确认及提交不使用隐藏价格 |
| TWAP 时间输入 | 天、时、分 | 时、分，可输入至 168 小时 | 保留现有时/分模型及 5 分钟至 7 天限制 |
| TWAP 摘要 | 桌面运行时间、约每笔数量、费用；手机运行时间、约每笔数量 | 手机额外显示订单价值、保证金；与桌面内容不同 | 双端统一频率、运行时间、启用的价格条件、费用；本次不新增近似子单数量算法 |
| Scale 顺序 | 数量在价格区间前；数量/偏斜参数相邻 | 桌面和手机顺序、参数排列不同 | 双端数量在前；起止价格之后，订单数/数量偏斜同一行 |
| Scale 摘要 | 价格、价值、保证金、费用；参数不重复 | 手机重复订单数、偏斜 | 共用紧凑摘要，参数保留在输入区和确认信息 |
| TIF / 只减仓 / TP/SL | 按订单能力显示，TIF 位于选项区 | 桌面 TIF 另列 chips，手机 TIF 窄屏隐藏标签 | 共用下拉菜单；只减仓/TIF 一行，TP/SL 在下一行 |

| 条件单摘要 | 显示适用的交易估算 | 手机部分条件单缺少清算价行 | 普通杠杆条件单与桌面保留相同清算价行；现有算法不提供条件单估算时显示占位符 |
| 手机空余高度 | 表单内容紧凑，较长表单随页面延伸 | justify-between 把剩余高度分摊到功能块之间 | 固定字段间距；剩余空间留在摘要前；表单和盘口一起增高 |
| 跨断点草稿 | 检查内容应连贯 | 手机数量/只减仓在本地状态，单位独立初始化 | 数量、单位、只减仓统一使用共享草稿，避免重挂载丢失或单位错配 |

## 八类订单的最终布局

两端共有：订单类型、适用的保证金/杠杆/账户控制、买卖方向、可用余额。手机把订单类型与保证金/杠杆放在紧凑首行，桌面保留分层工具栏。较长订单名称可截断，但菜单、可访问名称和标题保留完整名称。

| 订单 | 主字段（从上到下） | 选项 | 摘要 |
| --- | --- | --- | --- |
| 市场 | 数量、比例 | 只减仓、TP/SL | 清算价、价值、保证金、滑点、费用；按市场能力显示 |
| 限价 | 限价及 Mid、数量、比例 | 只减仓/TIF、TP/SL | 同上 |
| 止损市价 | 触发价、数量、比例 | 只减仓 | 普通杠杆订单摘要（清算价保留占位符） |
| 止损限价 | 触发价、限价及 Mid、数量、比例 | 只减仓 | 普通杠杆订单摘要（清算价保留占位符） |
| 止盈市价 | 触发价、数量、比例 | 只减仓 | 普通杠杆订单摘要（清算价保留占位符） |
| 止盈限价 | 触发价、限价及 Mid、数量、比例 | 只减仓 | 普通杠杆订单摘要（清算价保留占位符） |
| TWAP | 数量、比例、小时/分钟、随机化与只减仓、高级设置 | 高级设置展开触发价、最高价（多）/最低价（空） | 频率、时长、有效价格条件、费用 |
| 分段订单 | 数量、比例、起始价、结束价、订单数/数量偏斜 | 起止价 Mid、只减仓/TIF | 起止价、价值、保证金、费用 |

现货按原有能力隐藏保证金、杠杆、只减仓、清算价等不适用功能，不为了视觉一致添加不可执行选项。允许的 TIF 集合、定价精度、订单数量限制与执行协议不变。

## 交互细节

- 移动首行高 35px，采用 `minmax(0, 1fr) minmax(0, 1fr) auto`：订单类型和保证金均分剩余宽度，杠杆按内容占宽。字号 12px，文字与 9×6px 箭头间距 12px；长名称截断，保留完整菜单名称和标题。
- 首行到多空外框间距 2px，多空外框高 33px，内部按钮高 31px，点击范围不向相邻行扩展。可用余额距外框 8px，展示行高 15px，独立的 24px 点击区上下各扩展 4.5px，不侵入相邻控件。首行顶部至余额行底部总高 93px，与 375px 窗口下的 Hyperliquid 实测一致；桌面密度和行为保持原样。
- TP 与 SL 独立选择收益百分比或抵押资产金额；默认 USDC 沿用 `$` 显示，其他抵押资产显示其符号。选中当前单位不重复转换；切换一行不更改另一行单位，也不重设触发价格。
- 价格和收益标签在填写后仍保留；错误关联对应输入。单位菜单区域位于框内，不用越界热区覆盖相邻输入。
- TP/SL 两端均按 40% / 60% 分配价格列和收益列，为收益数值与单位留出空间；收益输入至少保留 32px。320px 下完整显示 USDH，过长资产名称在触发器中截断，菜单保留完整名称。
- 订单数范围 2–20、偏斜范围 0.01–100 常驻显示；保留键盘增减及边界校验。
- 移动 TWAP 的随机化、只减仓、高级设置固定为一个纵向组，各行最小高度 24px，方框 16px、文字间距 8px，常规单行文案下整组高 72px。控制点击区限定为 24×24px，不覆盖相邻选项；中英文保持相同顺序和对齐，长文案允许行高自然增长。时间输入与选项组间距 8px；桌面保留原有前两项横向布局和独立高级设置。该点击尺寸采用 [WCAG 2.2 AA 最小目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)，不照搬参考页面约 20.5px 的中心间距。
- TWAP 高级开关关闭时只保留原始草稿；实际有效值为空。重新展开恢复输入，切换多空同步最高/最低价标签。
- 桌面 CTA 在摘要前，手机 CTA 在摘要后；这是空间与导航差异，不要求两端所有像素位置相同。桌面固定网格，手机单一页面滚动；输入法打开或小屏允许页面滚动到动作按钮。
- 市场单滑点：桌面分别显示估算值与上限，手机合并为一行，仍可打开滑点设置。
- 数量校验提示与滑杆手势：桌面的提示行位于数量框与滑杆之间，出现或消失会让滑杆行上下移动 24px。滑杆手势期间这一行的有无与高度冻结在手势开始时的状态：开始时没有的，拖动中不出现，松手后按当前校验结果显示；开始时已有的，保留这一行并固定为按下时量到的高度（多行提示清空后不缩回一行，更长的提示在手势期间被裁切），内容随当前校验更新，没有错误时留空占位，松手后再移除或恢复自然高度。红框与 `aria-invalid` / `aria-describedby` 只跟随实际显示的内容。提交按钮的可用性与执行前校验不受影响，仍按真实校验结果判断。手机端的提示位于动作按钮上方，出现与消失不移动滑杆和按钮（实测两者位置不变），保持实时显示。
- 切语言保留协议值；切订单类型保留兼容草稿，并遵循原有能力约束：切到条件单关闭附带 TP/SL，切到 Scale 时不支持的 IOC 恢复为 GTC。桌面/手机断点重挂载保留数量及单位。市场变化或有效的成功回执通过既有共享重置机制清空草稿，旧请求回执不能清除新草稿。

## 只减仓数量与可用性（2026-09-21）

桌面和移动端从 `getReduceOnlyCapacity` / `useOrderEntryData` 共用持仓容量：成功且未过期的精确账户/网络订阅、coin/dex 匹配的原始 signed size，按 szDecimals 向下量化；多仓只能卖、空仓只能买，无仓位、错方向、不可判定快照分开。Max 与百分比以此容量为分母，开仓余额/杠杆不参与。余额行仍展示账户余额；数值为零不能锁死只减仓开关、有效减仓输入或把只减仓主按钮变成充值。

余额展示和桌面 Swap 仅使用 `isBalanceAvailabilityBlocked`；`isAvailabilityBlocked` 仍组合余额流与只减仓持仓门槛，供数量控件和交易动作使用。健康余额不能因为持仓快照缺失、错误或陈旧而变成零，数据恢复也不重置草稿。余额 Max 的可访问名称和 title 随模式切换：普通为“使用全部可用余额”，只减仓为“使用最大可减仓数量”，语言切换在同一个按钮实例上生效。

开关与方向改变保留手输数量，超额不裁剪；提交仍保留签名、账户模式、地区和数据可用性守卫。不可判定状态只显示原占位并阻止动作；已知无仓、错方向和超额使用订阅语言的字段反馈。只减仓保证金为 `—`，费用、价值、滑点仍展示；强平价模型不扩展。

普通手机订单保证金保留原有价格口径：共享 Hook 的 `conversionPrice`（限价类的有效限价，其余为标记价）进入 Big.js 域计算，触发价和 Scale 区间中点不改变该估算。只减仓返回不适用；TWAP 摘要继续不展示保证金行。此修复不改变桌面现有估算模型或交易所保证金规则。

入口执行守卫对市价、限价、四类条件单、TWAP 和 Scale 的主单复核最新持仓，Scale 合计检查；`normalTpsl` 子单不重复占用当前仓位。减仓主单不比较普通开仓容量，但仍要求原可用性上下文成功且新鲜；普通主单继续检查原方向容量。`r=true` 保持协议保护，不代表保证成交。TWAP 时间/最低价值规则继续生效，不新增小额平仓豁免。

设计、备选与验收范围见[修复方案](reduce-only-repair-plan.md)。

持仓来源先核对快照 owner、dex/coin 唯一身份、结构与原始数量字符串；错账户或畸形帧保留错误门槛，不归一化为已确认空仓。只减仓执行时再按本地 receipt time 验证快照新鲜度。

## 未平仓量上限限制（2026-09-27）

双端共用同一条规则与同一份数据：`useOrderEntryData` 从现有 `webData3` 快照派生 `isOpenInterestCapped`，两端把它传给 `perpInput` 的必填字段 `openInterestCapped`（共用 `limitOrderOpenInterestCapValidator`），并写入 `EntryOrderExecutionState.openInterestCapped`（共用 `assertEntryOrderExecutionAllowed` 复核）。两个字段都是必填，任何一端漏传都会在类型检查时失败。

只有当前、成功、同账户的快照列出该永续或 HIP-3 市场时，限价、止损限价、止盈限价（只减仓与所有 TIF 都不豁免）才显示限制说明并禁用提交；市价、止损市价、止盈市价、TWAP、分段与现货不受影响；未知快照与改动前完全相同。提示位置沿用各端已有的校验行：桌面在底部动作区 CTA 之上的错误行，手机在动作按钮上方的 `role="alert"` 行。CTA 名称保持 `Place … Order` / 方向标签，由 `canSubmit` 禁用。提示只取决于订单类型与快照，不影响数量控件的 `aria-invalid`，也不在滑杆手势中移动滑杆。切换市场重新判定，不重置草稿与订单类型。

真实组件回归：`tests/trade-panel-open-interest-cap.test.tsx`（桌面）与 `tests/mobile-trade-size-validation-a11y.test.tsx`（移动）覆盖上限时的说明、禁用与未提交，市价单保持可用，未上限保持原状，执行守卫读取最新快照，以及语言热切换时同一节点更新。约 130 字符的说明在 1001px 与 320px 下可能折成三行，尚未用浏览器布局套件核对。设计与取舍见 [OI 上限说明](open-interest-cap.md) 与 [ADR 0023](adr/0023-open-interest-cap-advisory-check.md)。
