# 公告功能实现方案：参照官方终端的静态公告源

状态：拟议，未实施；四项事项待产品负责人决定（见「需要决定」）。日期：2026-09-30。范围：终端（`apps/terminal`）的公告列表与详情页、导航入口、已读状态、新公告提示，以及公告内容的编写与发布。官方做法的取证与证据边界见[任务记录](work-memory/sessions/2026-09-30-official-terminal-announcements-trace.md)，本文引用的官方事实都只代表 2026-09-30 当日。

## 目标

- 用户能在终端里读到 Sairn 的公告：产品更新、市场上架与下架、维护与事故通知。
- 有新公告时提示一次，不打断交易，不遮挡下单与持仓操作。
- 发一条公告不需要发布应用版本，也不需要服务端状态。

## 非目标

- 账户级通知（官方的 `notification` 订阅）、浏览器推送、未读计数、搜索、评论、RSS。
- 运行时直接读取官方公告源。这是备选方案 B，未采用，理由见「备选方案」。
- 公告正文里的图片。第一版只有文字与链接。

## 约束

- 应用所在的源保存着 Agent 密钥与会话，公告正文不得以 HTML 字符串注入页面。
- 公告是被动数据：加载、失败、过期都不显示文字、图标或错误（[移动端数据展示](mobile-data-presentation.md)）；新增一类被动提示之前要先更新该文档。
- 应用反馈共用根部的 Sonner 宿主，不另建定位层（[全局操作通知](trading-notifications.md)）。
- 启动阶段不增加等待项；`/trade` 首次渲染的懒加载集合不因公告变大（[启动渲染规则](../.claude/rules/startup-rendering.md)）。
- 文案随语言热切换，日期经 `lib/format.ts` 跟随界面语言（[运行时翻译](i18n-presentation.md)、[数字格式设置](number-format-setting.md)）。
- 静态托管不变：不新增 `/api/*` 处理器，不改 CSP（[ADR 0005](adr/0005-spa-static-shell.md)）。
- 官方前端的未公开数据既不是接口契约，也不是再分发许可（[资产资料来源](spot-asset-information.md)的既有立场）。

## 官方做法与取舍

| 官方做法 | Sairn | 理由 |
| --- | --- | --- |
| 独立 CDN 上的静态 JSON：列表 `entries.json`，详情 `entry-<uuid>.json` | 采用同样的结构，放在应用同源的 `/feeds/announcements/` 前缀下 | 无服务端、同源不需要改 CSP；文件形路径由现有边缘函数直达 S3，缺失对象返回 404 |
| 正文是 Draft.js 原始内容，转成 HTML 后用 `dangerouslySetInnerHTML` 注入，产物里查不到净化 | 正文是 Markdown，用现有的 `renderMarkdown` 渲染成 React 节点 | 不产生 HTML 字符串；复用法律页已有的渲染器与样式 |
| 图片以 base64 内嵌在详情 JSON 里，单条可达 1.6 MB | 第一版不支持图片 | 避免大响应；以后需要时用同源图片文件 |
| 根部 Provider 裸 `fetch` 加 `setInterval` 每 5 分钟轮询，不看页面可见性，已读变化会触发重拉 | React Query，5 分钟过期与轮询间隔，后台标签页不轮询，已读变化不重拉 | 少发无意义请求；沿用项目的数据层 |
| 列表请求靠随机参数绕缓存 | 对象写入 `Cache-Control`，不加随机参数 | Sairn 上传时本来就写对象级缓存策略 |
| 已读存 `localStorage`，元素是 `hash ?? uuid`，编辑公告会改变 `hash` 并重新变成未读 | 已读存校验过的持久化仓库，元素是 `id@revision`，修订号由作者决定 | 改错别字不应重新打扰所有用户 |
| 全新访客所有历史公告都算未读，首次打开任何页面都弹浮层 | 只有最近 14 天内发布且未读的公告才提示 | 新访客不应被历史公告打扰；已读集合也因此有界 |
| 浮层是右下角的独立固定层，手机上贴底 | 桌面渲染进共享的 Sonner 宿主；手机不弹层，只在导航入口显示圆点 | 独立层会与通知堆叠重叠；手机贴底卡片会挡住下单与持仓区域 |
| 手机没有分类筛选（渲染条件恒为假） | 手机提供同样的分类筛选 | 官方的是缺陷，不照搬 |
| 失败与空列表都显示 `1-0 of 0` | 失败时保持空白并 `aria-busy`；只有成功的空快照才显示空态文案 | 空态结论需要完整、成功的快照 |
| 正文和分类徽章只有英文，日期跟浏览器语言 | 标题、摘要、正文按界面语言取，缺失时回退英文；分类与日期跟界面语言 | 项目的多语言与日期契约 |
| 路由 `/announcements` 与 `/announcement/:uuid` | `/announcements` 与 `/announcements/$id` | 条目 id 与官方不同，路径对齐没有意义；嵌套路径让导航高亮按前缀匹配 |

## 方案

### 内容模型

列表 `entries.json`：

```json
{
  "version": 1,
  "entries": [
    {
      "id": "2026-10-08-trailing-stop",
      "revision": 1,
      "category": "updates",
      "createdAt": "2026-10-08T06:00:00.000Z",
      "title": { "en": "…", "zh": "…" },
      "preview": { "en": "…", "zh": "…" }
    }
  ]
}
```

详情 `entry-<id>.json` 在同样的字段之外加 `content`（每种语言一段 Markdown）和可选的 `source`（指向官方公告或文档的 HTTPS 链接）。

- `category` 只有 `updates`、`listings`、`delistings`，与官方一致；新增分类要升 `version`。
- 列表按 `createdAt` 倒序生成，客户端不再排序。
- `en` 必填，其它语言可缺。
- 客户端用 zod 校验响应；`version` 不认识或校验失败按「不可用」处理，保持安静。旧壳因此不会被将来的结构变化弄坏。

### 编写与发布

- 内容放在仓库根目录 `announcements/<id>/`：`meta.json`（分类、时间、修订号、可选来源链接）加每种语言一个 Markdown 文件，与 `legal/` 的做法一致，改动经评审后才合入。
- `pnpm announcements:build` 校验并生成公告源到 `apps/terminal/public/feeds/announcements/`（Git 忽略）。开发服务器与本地预览读同一目录。校验项：id 与文件名格式、时间有效、`en` 存在、标题与摘要长度上限、链接只能是 HTTPS 或应用内绝对路径、不含原始 HTML。
- `deploy.mjs` 新增 `announcements` 子命令：只同步 `feeds/announcements/` 前缀，缓存策略与壳相同，随后只失效该前缀；默认演练，`--execute` 才写入。
- 应用的 `sync` 跳过 `feeds/`，这样从较旧提交发布应用不会把公告源回滚。`verify` 增加一项：`entries.json` 返回 200、缓存头正确、结构通过校验。
- 公告源在主网与测试网两个桶各发一次，内容相同。

### 客户端读取

- 配置集中在 `config/announcements.ts`：源路径、轮询间隔、每页条数、提示窗口天数、提示条数上限。
- `lib/announcements/` 放纯函数：响应校验、按语言取文案、未读与提示候选的计算、已读集合的裁剪。
- `hooks/` 里两个查询：列表（过期与轮询间隔 5 分钟，后台不轮询）和详情（只在详情路由启用）。查询键不带 `persisted` 前缀，不进入离线缓存。
- 列表请求在应用揭示之后发出，不加入 `bootTradeRoute` 与 `bootDashboardRoute` 的等待集合。

### 页面与入口

- 路由沿用金库页的嵌套写法：`announcements.tsx`（布局）、`announcements.index.tsx`、`announcements.$id.tsx`，都用 `bootDashboardRoute` 与 `buildPageHead`。
- 页面用 `DashboardFrameView` 加一个新的帧预设；视图是只收 props 的纯视图，控制器 hook 负责数据与状态。
- 列表每行是标题、分类徽章、摘要、日期；每页 10 条，前端切片分页；分类筛选是纯前端过滤，桌面在左栏，手机在列表上方。
- 详情是独立路由，顶部有返回列表的面包屑，正文容器在回退英文时带 `lang="en" dir="ltr"`。
- 入口：桌面 `DESKTOP_NAV_ITEMS` 的 `more` 分组增加一项（按前缀高亮），手机抽屉的 More 分组增加一项。页脚不加。

### 已读状态

- 新增持久化仓库 `use-announcement-read-store`，存 `id@revision` 数组，用 `createValidatedStorage` 校验。
- 写入时机：列表页用成功的快照渲染后，把当前列表全部记为已读；打开详情记该条；关闭提示记被提示的条目。
- 每次列表成功返回后，把已读集合裁剪到当前列表里仍存在的条目。
- 不做跨标签页同步；另一个标签页下次加载时读取到最新值。

### 新公告提示

- 候选：`createdAt` 在最近 14 天内、未读、来自成功的列表快照，取最新 3 条。
- 桌面：`AppToaster` 里增加一个桥接组件，向 Sonner 渲染一条固定 id、不自动消失的提示，列出候选标题；点标题进入详情，点关闭把候选记为已读。当前路径在 `/announcements` 下时不显示。
- 手机：不弹层。抽屉按钮和抽屉里的公告入口在有候选时显示一个圆点，进入列表页后消失。
- 提示不参与任何操作守卫，关闭它不影响交易通知的堆叠与任务状态。
- 实施前先给[移动端数据展示](mobile-data-presentation.md)的规则表和[全局操作通知](trading-notifications.md)的路由表各加一行。

### 被动数据状态

| 情况 | 展示 |
| --- | --- |
| 列表首次加载、失败、过期 | 标题与筛选保留，列表区空白并 `aria-busy`，不显示分页、错误或重试 |
| 列表成功且为空 | 空态文案 |
| 详情加载中或网络失败 | 面包屑保留，正文区空白并 `aria-busy` |
| 详情确认不存在（同源 404） | 以 `replace` 回到列表 |
| 列表不可用时的提示与圆点 | 都不显示 |

### 多语言与日期

- 外壳文案走 Lingui，六种语言都要有译文；分类标签由已知集合翻译。
- 标题、摘要、正文取当前界面语言，缺失时回退英文；切换语言不重挂载页面。
- 日期用 `formatDateTime(createdAt, { dateStyle: "medium" })`。

### 启动与包体

- 页面是路由级懒加载块。列表查询、已读仓库、提示桥接随运行时浮层加载，不进入启动闭包。
- 路由树新增路径可能让 Rollup 重新拆分共享块，实施时以 `pnpm build` 的分块环与包体预算检查为准；超预算时把提示桥接改为空闲后加载。

## 分步实施

1. **内容管线与页面**：内容目录、生成与校验脚本、`announcements` 发布子命令、路由与页面、导航入口、已读仓库。完成后即可发布公告，没有任何主动提示。
2. **新公告提示**：先更新两份规范，再做桌面 Sonner 提示与手机圆点。
3. **官方上架与下架条目**（取决于决定 1）：默认做法是由运营方写项目自己的摘要并用 `source` 链接到官方公告。

每一步结束时同步 `CHANGELOG.md` 的 Unreleased。数据源的取舍在第一步实施时写成 ADR 0025。

## 需要决定

1. **数据来源**。推荐：Sairn 自己的公告源，官方公告用自写摘要加外链。备选：上架与下架两类直接读取官方源（方案 B），前提是先确认可以再分发。
2. **内容放在哪里、怎么发**。推荐：放在本仓库，经评审后用独立命令发布，不随应用版本。备选：只随应用版本发布（少一个命令，但紧急通知要走完整发版）。
3. **提示形式**。推荐：桌面 Sonner 提示，手机只有圆点。备选：两端都用提示；或第一版完全不做提示。
4. **内容语言**。推荐：英文必填、中文尽量提供，其余语言回退英文。备选：六种语言全部必填。

## 备选方案

- **B：运行时直接读取官方公告源**。优点是零运营成本，上架与下架信息即时同步。未采用的原因：该地址是未公开的前端数据，随时可能变；把官方正文原样显示在 Sairn 品牌下需要再分发许可；`Updates` 类描述的是官方界面的功能，对 Sairn 未必成立；正文只有英文；要在保存密钥的源里渲染第三方富文本，需要自写 Draft.js 白名单渲染器、改写指向官方站的站内链接，并在 CSP `connect-src` 增加一个不透明的 CloudFront 主机名。
- **C：经 `/api/announcements` 代理官方源**。可以在服务端归一化并缓存，但再分发与内容适用性的问题不变，还增加一个 Lambda 处理器。
- **D：把公告打进应用包**（像法律页那样构建期导入）。最简单，但每条公告都要发版，用户还要等到拿到新壳才看得到，不适合维护与事故通知。

## 验证标准

- 单元测试：响应校验（含未知 `version`）、按语言取文案与英文回退、未读与提示候选计算（含 14 天边界）、已读裁剪、生成脚本的每条拒绝规则。
- 组件测试：纯视图；列表失败、过期、成功为空三种状态的展示符合上表；详情 404 回到列表；语言热切换不重挂载；提示桥接只在成功快照且有候选时渲染、在公告路由下不渲染、关闭后写入已读。
- 契约测试：公告组件与 `lib/announcements/` 内不出现 `dangerouslySetInnerHTML`；公告查询键不被 `shouldPersistQuery` 接受。
- 既有回归：导航（`top-nav`、`mobile-nav-drawer`、`desktop-nav-layout`）、启动渲染、运行时翻译、移动端数据展示、`pnpm test:cloudfront`。
- 构建：`pnpm build` 的分块环与包体预算通过。
- 浏览器：390、1000、1001、1440 宽度下检查列表、详情、提示与通知同时出现时的堆叠；写明输入路径。
- 发布：演练与 `--execute` 各一次；确认应用 `sync` 不触碰 `feeds/`；`verify` 的公告源检查通过。
