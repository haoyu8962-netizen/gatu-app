# 官网首屏原型：Open Book + Live Window（A 克制版 / B 大胆版）

状态：设计原型，供运营方在[官网重建规划](../../docs/website-rebuild-plan.md)第 21 节的视觉决定（D3 画布、D4 字体、D5 琥珀）之间对比选择。**不是生产代码，不进官网构建，不发布。** 日期：2026-10-24。

## 运行

1. 在 Claude 桌面应用里用预览配置 `design-handoff`（`.claude/launch.json`，Python 静态服务器，端口 3020，根目录 `designs/`）；或在仓库根目录运行 `python3 -m http.server 3020 --bind 127.0.0.1 --directory designs`。
2. 打开 `http://localhost:3020/website-hero-prototype/?v=a`（克制版）或 `?v=b`（大胆版）。页面底部的切换条或键盘 `1` / `2` 随时切换；`&coin=ETH` 等参数选择初始市场。
3. 画布需要真实的 Hyperliquid 公共数据，打开后约 30–120 秒画面才铺满 2 分钟窗口（不回填历史，见下文）。

## 两版的差别

| 项目 | A 克制版（规划第 9 节的推荐默认） | B 大胆版（需要运营方改变 D5 等决定） |
| --- | --- | --- |
| 页面底色 | 石墨 `#12131a`；产品窗口用终端 `#0F1A1F` | 青黑 `#091114`，64px 网格底纹，窗口下方 5% 的暖色光 |
| 版式 | 左 5 列文案、右 7 列实时窗口 | 标题居中、两行；实时窗口全宽，1440×900 下窗口顶边约在 480px |
| 标题 | IBM Plex Sans 500，最大 50px，全白 | IBM Plex Sans 600，最大 56px，灰白双色（「independent web terminal.」为白色） |
| Open Book 挂单热度 | 暗中性灰阶（买卖两侧 12% 色调） | 琥珀色梯度（暗褐 → `#E6B766` → 近白），这是 B 唯一用琥珀的地方之一 |
| 成交点 | 买单 `#27d29f` 实心点、卖单 `#f08b9e` 空心环，外圈一道底色描边 | 形状与颜色同 A，下面多一层 50% 的同色柔光 |
| 中间价线 | 纯白 1.5px，下面一道底色衬线，是画面里唯一的白线 | 同 A，另加一道柔光；「现在」处一个静态琥珀光点与琥珀色时间边 |
| 网格 | 无 | 15 秒竖线随数据滚动（对齐整 15 秒），横线与价格刻度同步 |
| 入场动效 | 文案与窗口 400 ms 淡入上移 | 同 A，窗口另加 0.99→1 的缩放 |
| 与规划的关系 | 符合规划第 7–9 节的默认值 | 琥珀只用于流动性热度与「现在」标记，仍需修订 [ADR 0028](../../docs/adr/0028-brand-accent-colors.md)（决定 D5）；整页青黑底与网格对应决定 D3 的备选 |

两版共用：
- 英文文案草稿（规划第 6 节，D7 待定）、IBM Plex Sans（D4 推荐）、中性色主按钮（ADR 0028 决策 3）；
- 风险句与「需要 Arbitrum 上的 USDC」紧贴按钮，独立声明与官方网址行在首屏；
- 画布上方带真实色样的图例，右侧 76px 价格刻度槽（中间价标签不压画布）；
- 「Pause」冻结画布与全部数字，「Read snapshot」把当前盘口读给读屏软件；
- 系统开启减少动态效果时画布停在一帧并写明「Still snapshot · 时间 UTC」，可点「Show live view」改看实时；
- 冷启动时时间轴从 15 秒起随数据长到 120 秒（手机 60 秒），第一秒就有内容。

## 数据

- 全部来自 Hyperliquid 公共接口，浏览器直连 `api.hyperliquid.xyz`，没有后端、没有分析脚本、不写浏览器存储。
- Worker 开两条 WebSocket（同一连接上不同参数的盘口帧无法区分，见 AGENTS.md 订单簿契约）：
  - 快速连接：`l2Book`（`nSigFigs: 5`、`fast: true`，前 5 档，约 0.5 秒一次）、`trades`、`activeAssetCtx`（24h 涨跌）；
  - 深度连接：`l2Book`（`nSigFigs: 5`，20 档，2026-10-24 实测约每 5.3 秒才推送一次）。
  - 每一列热度把两本簿合并：快速簿的价位优先；快速簿有满 5 档时，深度簿只取比快速簿最外档更外的价位；深度簿超过 8 秒没更新就不用。离中间价 14 档以外的热度逐渐淡出，避免 20 档的上限被读成「流动性到此为止」。
- 价格步长按 Hyperliquid 规则推算（5 位有效数字，并受 `6 − szDecimals` 小数位上限约束；四个币的 `szDecimals` 暂时写死），不从价格字符串的位数推断。
- 首次进入（以及切换市场后 300 ms，去抖）用 REST `l2Book` 与 `recentTrades` 播种，切换时取消上一次请求；24h 走势线（REST `candleSnapshot`）同样去抖，并按市场缓存 10 分钟。连按 6 次方向键切换市场，实测只发出 3 个 REST 请求。
- 订阅后第一条 `trades` 消息是历史快照（最多约 30 笔、可早至 80 多秒前），按交易所时间放回各自的位置；所有成交按 `时间:tid` 去重。`recentTrades` 返回的双方地址（`users`）与 `hash` 直接丢弃，不显示也不保存。
- Fail closed：快速簿超过 4 秒没有有效帧就去掉 LIVE 标记并隐藏价格、涨跌、盘口与刻度；15 秒无数据则清空并重新播种；从不显示「—」「...」或 0 之类的占位值。校验拒绝非十进制字符串、乱序或交叉的盘口与旧于上一帧的帧，连续 3 帧无效就重连。
- 连接：退避带随机抖动（最长 30 秒），收到第一帧有效数据才重置；每条连接 60 秒内最多 3 次、5 分钟内最多 6 次新建，超过就停止（fail closed）；打开但 30 秒没有任何消息就主动重连；`error` 消息触发重连；页面隐藏 30 秒后断开两条连接，回到页面时重新播种。
- 纵轴覆盖窗口内的全部中间价并留出盘口深度的余量，最多每 10 秒调整一次；当前价格冲出视图时最快每秒调整一次，且总把当前价放在视图内。
- 原型在价格合计、价差与涨跌幅上用了 JavaScript 浮点数；生产实现按仓库规则改用 Big.js 与协议字符串。

## 实测（2026-10-24，Agent 执行）

- 仓库的 Playwright 无头 Chromium（`apps/terminal` 的 `@playwright/test`），桌面 1440×900 与手机 390×844（DPR 2）：
  - 每种约 100 秒（手机约 70 秒）：控制台零错误；页面无横向溢出；LIVE 状态逐秒采样 0 次中断（桌面 94 次、手机 64 次采样）。
  - 暂停：3 秒内画布像素、最新价与盘口都不变，标记显示「PAUSED」，取消暂停后恢复移动。
  - 减少动态效果（`reducedMotion: 'reduce'`）：A、B 的画布与整个舞台 4 秒内像素不变；点「Show live view」后恢复实时，焦点移到 Pause。
  - HYPE：步长显示 `0.001`、中间价 `75.8685`；冷启动 2.5 秒时图例为「last 15 s」。
- 这些是无头浏览器的结果，不是真机：Safari、Firefox、iOS 低电量模式、真实触控、长时间运行的内存与耗电都没有测。截图在会话临时目录，不进仓库。
- 一轮三视角审查（数据与资源、无障碍与动效安全、设计）提出的必须项都已修正：订阅后的成交快照被画在「现在」处、暂停与减少动态时画布仍在动、快速切换市场会用光每分钟 REST 额度、静默断线不重连、热度与成交按不同基准定位而错位、价格精度从字符串位数推断、B 的卖单丢了空心形状、B 的琥珀用在 8 个地方、A 的中间价线认不出、标签焦点环被裁掉、盘口深度条按单元格拆成两段等。

## 与生产实现的差距（规划第 7、10、19 节）

- 没有「Recorded <日期>」海报与海报生成管线；不支持 OffscreenCanvas 的浏览器只显示一句说明。
- 两条连接与规划「每页一个连接」不同，取舍见规划第 10 节「2026-10-24 原型实测（追加）」；没有 Web Lock 多标签页单连接、没有按字节的数据调速器、手机没有改用 `bbo`。
- 没有单元测试、故障矩阵测试与契约测试；渲染每个采样周期整体重绘热度层（最多约 480 列），没有做位移增量绘制。
- 「Deposit guide」链接只是占位（规划阶段 2 的页面）；没有桌面二维码；「Read snapshot」在手机上隐藏。
- 键盘 `1` / `2` 只在焦点不在页面控件上、且没有按修饰键时切换版本。
