# Startup rendering

Owner: `docs/adr/0010-blank-until-ready-startup.md`. Applies to application startup, route pending UI and trade market readiness.

- All application routes prerender and hydrate the same visually empty `StartupFallback`: `aria-busy="true"` and one `<output className="sr-only">Loading Sairn...</output>` (the name comes from `BRAND_NAME`, `brand/brand.json``. No visible nav, header, footer, market chrome, skeletons, animation or timers before runtime and the persisted locale catalog are ready.
- The `/trade` route reveals only after `bootTradeRoute` settles: it awaits every lazy piece of the first terminal render (workspace panels, footer, navigation pieces, global modals, runtime overlays) up to `TRADE_ROUTE_REVEAL_BUDGET_MS`, so the retry render after hydration commits without suspending and React's 300 ms fallback throttle never applies (ADR 0012). New lazy pieces on the first render must join that preload set; catalog and order-book requests stay fire-and-forget.
- Preserve the theme bootstrap, head/font/module preloads, Service Worker registration and shell caching. Only the SPA shell is prerendered: Docs, Support and the legal pages are dashboard routes with the same empty announcement and real application chrome (ADR 0020); never force an application route to reproduce terminal chrome for hydration.
- Render real chrome first in the persisted locale/theme. Desktop uses `DesktopTerminalFrameView`, TopNav/FooterBar in market-loading mode and an empty busy workspace. Mobile uses the same `MobileTerminalFrameView`, MobileHeader and MobileBottomNav (validated persisted navigation state) in both phases. Replace only workspace contents when market data is ready; header/footer/nav DOM identity must survive.
- Dashboard chunk pending UI is the same empty announcement. Each loaded page owns its real DashboardFrameView and preset. Never introduce route-specific or language-specific startup skeletons.
- Real components keep props-only views as their single source of markup. Views remain pure and deterministic: no hooks, stores, subscriptions, Lingui runtime, browser globals, clocks or randomness. Translations and runtime state arrive as props.
- Preserve financial calculations, signer gates, freshness checks, unavailable-action guards, drafts and ordinary mounted data-component fallback values. Empty startup presentation is not evidence of an empty account.
- Webfonts are declared explicitly in `styles.css` with `font-display: block` (no fontsource `@import`). `StartupReadyGate` waits for the persisted locale catalog and the preloaded Inter/IBM Plex faces, capped by `FONT_READY_TIMEOUT_MS`, so the first paint already uses final text metrics; `MarketOverview` additionally stays pending until its IBM Plex faces are usable. Never reintroduce `swap` or paint chrome in a fallback font; `startup-font-display-contract` and `font-readiness` pin this. The gate's effect must call its reveal once after wiring the locale and font callbacks: if both conditions are already true when the effect runs (StrictMode's second effect pass, or fonts settling between render and effect), no callback fires and the page would stay blank; `root-startup-fallback` pins this.
- Regression tests: root-startup-fallback and root-route-transition cover route-independent empty output and hydration; trade-terminal-page-boot and top-nav cover chrome identity and Chinese first render; i18n-hot-switch and i18n-reactivity-contract protect live translations and pure views. Component tests retain keyboard, disabled, geometry and ref behavior. Measure empty fallback → real chrome → workspace with `tests/browser/boot-milestones.mjs`; report browser measurements separately from unit tests.
