## Startup placeholder parity

Owner: `docs/adr/0009-startup-placeholder-single-source.md`. Applies to every surface the prerendered shell (`AppShellSkeleton`), the runtime placeholders (`TerminalLoadingWorkspace`, `MobileLoadingFallback`) or the dashboard skeleton draws.

- **One view, two callers.** A startup-visible surface renders through a props-only view component (`*-view.tsx`). The runtime container computes props (data, translated labels, handlers) and renders the view; the shell and the runtime placeholders render the same view with placeholder props. Never write placeholder markup by hand and never copy class strings into a second tree.
- **Views are pure.** No hooks, no stores, no subscriptions, no Lingui runtime, no `window`/`document`, no clocks or randomness. Labels, values and state flags arrive as props. Given the same props a view must produce the same DOM (hydration stability).
- **Placeholder props have one source.** One constant object per surface: labels come from the same `msg` descriptors' English source (`.message`) in the prerendered shell or from `t` in runtime placeholders; values use `FALLBACK_VALUE_PLACEHOLDER` (`-`), names use `—`. Do not invent values the shell cannot know (`0.00`, `Perp`, `20x`, an active side). Runtime placeholders may pass persisted, synchronously readable UI state (active tab, nav item); the prerendered shell passes defaults.
- **Shell import boundary.** `app-shell-skeleton.tsx` and the dashboard skeleton may import only view components, `config/*`, `@/lib/cn`, `@phosphor-icons/react` and the brand logo. A source-contract test pins this.
- **Inert, not fake.** Views render real elements. The shell wraps its decorative tree in `aria-hidden="true"` plus the HTML `inert` attribute; it keeps `aria-busy`, one `<output class="sr-only">` announcement, no animation classes and no timers.
- **Parity is tested, not eyeballed.** Every view has a parity test rendering placeholder props and sample real props and asserting identical DOM structure and geometry-affecting classes (text, `data-*` and color classes may differ). Each migrated surface is measured with the Playwright box comparison at desktop 1440/1280/1030 and mobile 390/360/430, both themes, `en` and `zh`; only text-width deltas are allowed, and the numbers go into the task record.
- **Geometry sources.** Desktop panel rectangles keep coming from `desktop-grid-loading-surface.tsx` mirroring `config/desktop-grid-layout.ts`; everything inside a panel comes from its view.
- **Migration.** Until a surface is migrated its existing frame stays; migrate one surface per commit with view, container, placeholder constant, parity test and measurement. Delete `mobile-chrome-classes.ts` and `renderDesktopPanelFrame` once their surfaces are migrated.
